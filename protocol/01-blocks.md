# 01 · The Block Library

Eight blocks, one per technique in Anshu Chimala's *How to turn your AI into a world-class designer* (Lenny's Newsletter, Sep 1 2026), generalized beyond UI design.

Each block is a lego piece with:
- typed input and output **ports**;
- tunable **knobs**;
- known **failure modes**;
- **wiring rules** for how it can be sequenced, parallelized, looped or nested.

[02-grammar.md](02-grammar.md) defines the operators that connect the blocks. [03-configurations.md](03-configurations.md) wires them into configurations for specific use cases.

**How to read each block**
- **Keep from the article:** what the author actually says. This is the article-faithful core.
- **Additions ⟨A⟩:** the main things this protocol adds. Together with the inline marks, these are what you remove to get back to the article's version.
- Inline ⟨A⟩ marks a non-article step, knob value, guard or wiring rule where it appears.
- **Scope rule:** a block generalizes the article's technique and nothing more. Adjacent techniques found in research go in [05-more-to-explore.md](05-more-to-explore.md).

## The one idea underneath all eight

Preference-tuned models resolve every open decision with the most typical, please-everyone option. Annotators favor familiar text, and RLHF sharpens the model toward it (Zhang et al. 2025; Kirk et al. 2024). The same defaults recur across runs, users and even model families (the "Artificial Hivemind", Jiang et al., NeurIPS 2025). The article's answer, and its closing line, is to **focus on the feeling** the work evokes. Distinctiveness is the means, not the goal. Each block counters one way the pull toward the default shows up:

| Block | Code | Article technique | Stage | What it counters |
|---|---|---|---|---|
| External Seeding | `SEED` | T1 Seed strings | Diverge | Mode collapse: "be random" still returns the mode |
| Taste-Steered Brief | `VISION` | T2 Ambitious prompts | Diverge | Defaults filling every unspecified decision; human paste-back |
| Blind Critic Loop | `CRITIC` | T3 Subagent feedback loops | Deepen | Self-review bias; the generator deciding it's done |
| Specialist Asset | `ASSET` | T4 Image generation | Deepen | Agents faking assets in their own medium (code-drawn gradients and shapes) |
| Specialist Relay | `RELAY` | T5 Video generation | Deepen | Seams between independent generations; un-layerable outputs |
| Subtraction Pass | `CUT` | T6 Cut elements | Distill | Additive default; deleting feels risky to the model |
| Tell Sweep & Swap | `TELLS` | T7 Remove AI tells | Distill | Ubiquitous defaults that read as autopilot |
| Human Voice Pass | `VOICE` | T8 Rewrite copy by hand | Distill | One shared AI voice |

Two forces run through all eight.
- **Variety and taste come from outside the model's default**: a seed (SEED) or a human (VISION, CUT, VOICE).
- **Judgment is separated from production** (CRITIC, TELLS, CUT), because a model judging its own work in its own context anchors on its own process.

## SEED · External Seeding
*From T1 "Use seed strings to inject variety." Stage: Diverge.*

**Counters.** The block counters mode collapse at open decisions. Asking the model to "be unique" or "decide at random" has its own mode. In the article, all four "random" runs landed on the same pottery metaphor ("Kiln"). Other studies find the same pattern:
- LLM coin-flip sequences start with heads more than 88% of the time.
- High-temperature generation still produced a very repetitive dataset in TinyStories.

**Core move.** Get randomness the model must *interpret* (a random string), have it turn that string into explicit decisions on named axes, then execute that direction with judgment. The seed decides *what*; the model's skill decides *how well*.

**Procedure**
1. ⟨A⟩ **Use only on open-ended decisions,** where many outputs are equally valid. Never on single-answer work.
2. ⟨A⟩ *(Diagnostic)* Run the plain request N times in fresh contexts. Convergence on the same structure, palette or angle means seeding is warranted. The article ran this as a demonstration (plain ×4, then "random" ×4, then seeded ×4); here it becomes a pre-check.
3. **Name the decision axes** the seed drives (the article: color scheme, layout, typography, etc.). Separately list the fixed constraints the seed can't touch. ⟨A⟩ Include at least one structural axis, unless the configuration sets `structure=conservative`.
4. **Get a fresh string per branch.** Article default: a long random alphanumeric string generated by a shell script. With no shell, the model writes the string itself as its first step, which is the variant Sakana's SSoT paper actually tested. Never reuse a seed across branches.
5. **Map:** derive the direction from the string, looking "beyond the surface for subpatterns, special numbers, anything that inspires you." ⟨A⟩ Write the direction down for every axis before building.
6. **Execute:** "use your judgment to bring this direction to life and make it look great."
7. **Hide the seed:** it never appears in the artifact. ⟨A⟩ Log seed → direction → artifact outside the artifact.
8. **Hand off the population** to selection or deepening. Expect seeded drafts to still carry stale structure; the article sends them to the critic loop. ⟨A⟩ Re-roll weak branches with new seeds.

**Ports.** In: `intent` or `brief`, axes, constraints, string source, N. Out: `option_set<artifact>` plus direction notes.

**Knobs**
| Knob | Default | Range / notes |
|---|---|---|
| `branches` | 4 (article) | 3–8 |
| `string_source` | shell RNG (article) | model-written string (SSoT's tested form; co-default without a shell) |
| `seed_shape` | long random alphanumeric string | ⟨A⟩ 32–64 characters |
| `axes` | color, layout, typography, … (article) | ⟨A⟩ ≥1 structural axis unless `structure=conservative` |
| `structure` ⟨A⟩ | free (article-faithful) | `conservative`: an opt-in hypothesis, see C1 |
| `mapping_model` | reasoning-capable | SSoT reports weak results below about 8B parameters |
| `mode` ⟨A⟩ | interpretive (article) | *deck* (random draws of words, personas or constraint cards) or *indexed* (hash/mod into curated lists). These are variants with mixed evidence for LLMs; see 05 §A |

**Guards**
- *Pseudo-randomness by adjective.* The seed must be an actual string, never "be random."
- *Lazy mapping* (only the first characters drive the choice). Use the whole string and look for subpatterns; ⟨A⟩ require a direction per axis and check the spread across branches.
- *Surface-only variety.* Send the population to CRITIC (article). ⟨A⟩ Add a structural axis.
- *Seed overrides requirements.* Declare fixed constraints separately.
- *Seed leaks into the artifact.* "Don't reveal the string."
- ⟨A⟩ **Never seed a judge.** The critic's prompt stays identical every round.

**Fit by domain**
| Domain | Fit | Seed drives |
|---|---|---|
| UI / visual design | strong | palette, layout, type, imagery |
| Fiction / creative writing | strong | POV, setting, structure, central image |
| Naming & brand | strong | metaphor domain, sound profile, root language |
| Synthetic data / test generation | strong ⟨A⟩ deck/indexed | persona × features × values. The strongest evidence here (TinyStories, 1B Personas) is for the *deck* variant, not for the string seed |
| Marketing concepts | moderate | angle, format, register (concept level, not sentence level) |
| Product ideation | moderate | angles for the idea list (string); ⟨A⟩ deck lenses |
| Education material | moderate | contexts, scenario shapes; the objective stays fixed |
| Presentations | moderate | visual theme + narrative arc options |
| Software engineering | weak | exploratory spikes and generative content only; never correctness |
| Research reports | weak | which framing to stress-test next; never conclusions |

**Wiring.** Native form is parallel: `x4[ SEED > build ]`. Branches never see each other. It loops only as an outer re-roll. It can nest inside VISION's scatter step and inside ASSET/RELAY art direction. It never goes inside a judge (CRITIC) or a Distill block.

**Evidence.**
- Misaki & Akiba, *String Seed of Thought* (Sakana AI, ICLR 2026). The model writes a random string and manipulates it. This beat "prompted to be diverse," prompt paraphrasing and higher temperatures on NoveltyBench. The paper also compares external randomness with model-written strings, on two tasks that are not design work:
  - §5.1.2, a biased probabilistic-instruction test (DeepSeek-R1): model-written strings beat a fixed and an externally randomized string, though the randomized string also helped.
  - App. D.6, open-ended generation (DeepSeek-R1-0528 on NoveltyBench Curated): model-written strings beat a pseudo-random string injected into the prompt ("Seed Injection") and a random-string tool the model calls ("Tool Call", the closest analogue to the article's shell script) on distinctness and utility in every category except product recommendations. Both external forms still scored above no seed on overall utility.

  *The article's setup, a shell-generated string driving named design axes, has not been tested directly.* The comparisons above used one model family and no design task.
- Zhang et al., *Verbalized Sampling* (typicality bias).
- Jiang et al., *Artificial Hivemind* (NeurIPS 2025).
- "How Random is Random?" (arXiv 2406.00092).
- Eldan & Li, *TinyStories*: high temperature alone still gave a repetitive dataset, so the authors injected random words and features. This was a design observation, not a controlled comparison.

**Keep from the article.** The model can't act randomly, so variety comes from outside it. A shell-script string. The creative direction is derived from the string ("subpatterns, special numbers") before building. "Use your judgment… make it look great." The string is never revealed. The results (Meridian, zylo, Quartz, Quanta) are one-of-a-kind but "still rely on stale patterns," so the next step is the critic loop.

**Additions ⟨A⟩.** Open-ended-only rule. The diagnostic as a pre-check. A structural axis. The written direction per axis. The seed log. Re-rolling. The deck and indexed modes. Explicit fixed constraints. The `structure` knob. Never seeding a judge.

## VISION · Taste-Steered Brief
*From T2 "Be much more ambitious with your prompts." Stage: Diverge.*

**Counters.** Unspecified decisions get filled with the model's default. There's also a human-side failure: people anchor on AI-suggested ideas and paste them back.
- Stories written from AI-supplied ideas were rated more creative and better written, mostly among less creative writers, but they were more similar to one another (Doshi & Hauser, *Science Advances* 2024).
- More sophisticated prompting did not reduce this homogenization (Anderson et al. 2024).

**The human's own reactions are the active ingredient.**

**Core move.** Replace the model's on-the-fly decisions with a vivid, specific, deliberately unusual vision. Usually it's borrowed from an outside reference (a video game, an interior trend, an art installation) and steered by a human's taste. There are two routes:
- **Direct:** you write the ambitious prompt yourself.
- **System:** the AI scatters ideas, you react, the AI sharpens them, and the AI writes the build brief.

**Procedure**
- **Direct route (article examples a–c).** Imagine the inspiration and describe how it should shape the output, while keeping the artifact's function. The article's three: a landing page where each section is a pixel-art still from a video game (*Questlog*); a living isometric 3D city where features are buildings (*Skyline*); a radically asymmetric, dissonant page that "breaks all the rules and still looks good" (*Offcut*).
- **System route (article's 3 steps):**
  1. *Scatter.* The AI lists as many ideas as it can, broad not deep, intentionally lacking detail. The goal is to inspire your imagination.
  2. *React.* Visualize your favorites, note how you react (including what to avoid), and ask the AI to sharpen the direction "based on my tastes."
  3. *Compile.* Iterate until satisfied, then the AI writes a concise prompt an agent could use to build a first proof of concept.
- **Then build**, keep or discard, and **save prompts that didn't work** to retest on newer models.
- ⟨A⟩ Optional extras:
  - Write 1–3 of your own references *before* reading the AI list, to reduce fixation.
  - A uniqueness check: "Could someone pasting the obvious request have produced this brief?"
  - A *functional anchor* line in every brief (the article's "yet still functioning as a landing page," generalized).

**Ports.** In: `intent`, `taste` (required), optional references, optional `SEED` stimulus. Out: `brief` + taste record + proof-of-concept artifact(s) + `failed` archive entries.

**Knobs**
| Knob | Default | Notes |
|---|---|---|
| `route` | direct or system | system when you have no idea yet |
| `scatter_breadth` | "as many as you can" | ⟨A⟩ in practice 20–40 |
| `scatter_fidelity` | short label + one-line description | ⟨A⟩ never mockups at this stage: AI image support increased fixation in one study, which its authors partly attribute to high fidelity (Wadinambiarachchi et al., CHI 2024) |
| `reference_distance` | far (game, interior trend, art installation) | near = the subject's own materials (milder) |
| `ambition_ladder` ⟨A⟩ | themed → immersive → rule-breaking | mirrors the article's three examples |
| `sharpen_rounds` | until satisfied | |
| `brief_length` | concise | ⟨A⟩ ≤ ~200 words |

**Guards**
- *Paste-back homogenization.* Every round needs your own reactions, including what to avoid.
- *Fixation* ⟨A⟩: keep the scatter low-fidelity.
- *Gimmick over function* ⟨A⟩: always include a functional anchor.
- *Negatives as global bans.* Keep them specific to the direction ("not cartoony *for this* look").
- *Timidity.* "There's no way this will work" means you're on the right track (article).

**Fit by domain**
| Domain | Fit | Notes |
|---|---|---|
| UI / visual design | strong | the article's case |
| Fiction / long-form creative | strong | distant formal references (museum audio guide, ship's log) |
| Naming & brand | strong | scatter naming *territories*, not names |
| Presentations / keynotes | strong | one reference supplies both the visual system and the narrative spine |
| Product strategy | moderate | reframing from a distant domain; a vivid frame can seduce a team past validation |
| Education | moderate | the theme must serve the learning objective |
| Synthetic data / tests | moderate | "taste" = a tester's intuition about where systems break |
| Research reports | weak | framing and presentation only |
| Core software engineering | weak | predictability is a feature; useful for CLI tone and error copy |

**Wiring.** Partly parallel: the scatter step and the builds can fan out, but react/sharpen is serial because it runs at one human's pace. It can contain SEED in the scatter step. Its brief goes to builders and **is never shown to the CRITIC**. ⟨A⟩ The taste record later seeds VOICE's voice reference.

**Evidence.**
- Doshi & Hauser 2024.
- Anderson, Shah & Kreminski, C&C 2024.
- Wadinambiarachchi et al., CHI 2024.
- Atmakuru et al., *CS4* (more constraints keep models from retelling memorized narratives).
- Liu et al. 2026 (cross-domain distance helps humans more than LLMs).
- Zhou et al., *APE* (LLMs write prompts at human level, which supports delegating the brief's *wording*).

**Keep from the article.** Bring your own taste. The three direct examples. The three-step system with the Industrial Control Panel → "Precision Industrial" example. Pasting AI ideas back gets you what anyone could get; steering gets you something only you could create. Try ideas that sound terrible. Save failed prompts and retest them on new models.

**Additions ⟨A⟩.** References first. The uniqueness check. The functional anchor line. The ambition ladder. Numeric defaults. Taste record → voice reference.

## CRITIC · Blind Critic Loop
*From T3 "Create positive feedback loops with subagents." Stage: Deepen.*

**Counters.** An agent reviewing its own work in its own context judges what it remembers (its code, rationale and effort), not what the user experiences.
- Models favor their own generations (Panickssery et al. 2024).
- Same-model self-refinement amplifies that self-bias (Xu et al. 2024).
- LLMs are much worse at *locating* a mistake than at correcting one once its location is given (Tyen et al., Findings of ACL 2024, on reasoning traces). That is an analogy for taste critique, not a direct finding.
- A generator that grades itself praises mediocre work (Anthropic, *Harness design*, Mar 2026).

**Core move.** The worker agent keeps improving the artifact. Each round it consults a stronger **critic** in a fresh context that sees *only the rendered output*. The critic infers what the design is going for, imagines how a top studio would execute it, outlines the biggest gaps, and scores it out of 10. **The work is complete only when the critic independently reaches the threshold, and the threshold is never put in the critic's prompt.**

**Who holds the threshold.**
- *Article-faithful:* the worker is also the orchestrator. The threshold T sits in the worker's prompt and never in the critic's.
- ⟨A⟩ *Option:* an external script or stop hook holds T, and the worker sees only the critique.

**Procedure**
1. **Tiers.** The critic is a big, strong model, used only for executive decisions. The worker is a capable, cheaper model, but not too small.
2. **Render.** The article: capture a screenshot of the current design. In general this is the screenshot-equivalent: what the audience sees, reads or uses, with code, rationale, history and earlier critiques stripped out. ⟨A⟩ Capture every surface where quality lives (several viewports, pages, frames).
3. **Criteria ladder** (article):
   - **BAD:** "judge if it looks beautiful, not AI-generated." Too subjective; results swing.
   - **OK:** evaluate the intended aesthetic, imagine a top studio's execution, judge against that bar.
   - **GREAT:** "here are 5 designs: 4 professional examples and 1 of ours; rank them by polish and taste."
   - References can be comparable screenshots, designs you like, or AI concept art, and serve as **a baseline or moodboard, not a target**.
4. **Critic prompt, written once and reused.** It asks the critic to:
   - evaluate the aesthetic the design is going for (⟨A⟩ including the feeling it intends to evoke);
   - imagine a top studio's execution;
   - outline the biggest gaps;
   - give a score out of 10.

   Its guidance: consider structure and composition *and* fine details; penalize overdone or obviously AI-generated patterns; give tight, specific feedback; be bold and opinionated. **Never mention the threshold.**
5. **Worker contract.** "Improve this. Use the critic to decide what to focus on. You're done only when it independently scores ≥ T." T is 9/10 in the article.
6. **Iterate.** Render, spawn the critic fresh with the render, frozen prompt and fixed references, then the worker fixes the biggest gaps.
7. **Probe before scaling** (article): run one or two iterations first and check that it's converging. If it isn't, fix the stopping criteria, bar, prompt, render or worker before continuing. ⟨A⟩ If the prompt, references or critic model change, restart the score trajectory.
8. ⟨A⟩ **Exit and failure handling** follow [02 §2 Loop-until](02-grammar.md#2-operators): best snapshot, cap, hand-off to a human. Before choosing the "best" snapshot, re-rank the top 2–3 side by side in a single critic call, because absolute scores from separate calls are noisy.
9. ⟨A⟩ **Calibrate once before the probe.** Show the frozen critic 2–3 known-good references and 2–3 known-generic AI outputs. Proceed only if it orders them correctly.

**Ports.** In: `view` (critic only), optional `refs`. The `artifact` and the `brief` go to the worker only. Out: refined `artifact`, `score` trajectory (to the threshold holder), final `critique`.

**Knobs**
| Knob | Default | Notes |
|---|---|---|
| `critic_model` | biggest available (article: Claude Fable 5) | ⟨A⟩ consider a different model family for prose, where self-preference is strongest |
| `worker_model` | capable (article: Claude Opus 5) | if the same gaps repeat, upgrade the worker |
| `bar_mode` | OK (article's prompt) | GREAT whenever you have about 4 references (the article's "great" tip). Never BAD |
| `refs` | 0 (OK) · 4 + ours (GREAT, article) | ⟨A⟩ up to 10 |
| `threshold` | OK: score ≥ 9/10, hidden (article) | ⟨A⟩ GREAT: ours ranked 1st of (refs + 1), hidden |
| `probe` | 1–2 iterations (article) | |
| `max_iterations` ⟨A⟩ | 5 total, including the probe | the article sets no cap |
| `gaps_per_round` | "the biggest gaps" (article) | ⟨A⟩ 3–5 |
| `position_shuffle` ⟨A⟩ | on in GREAT mode | guard against position bias |

**Guards**
- *Critic never satisfied.* "Set stopping criteria carefully… try one or two iterations first" (article). ⟨A⟩ Cap, plateau detection, human hand-off.
- *Lenient or self-preferring critic.* Use a separate stronger model in a fresh context.
- *Score noise.* Climb the ladder, freeze the prompt, anchor with references.
- *Critic anchored on process.* Render-only input, every call.
- *Threshold leakage.* Keep T out of the critic prompt.
- *Homogenization* ⟨A⟩. Judge each artifact against *its own* intent. In Anthropic's harness, wording like "museum quality" made designs converge visually.
- ⟨A⟩ *Taste only.* CRITIC judges taste, not truth. Correctness needs separate verification (05 §C).
- ⟨A⟩ *Copy.* Where copy is a separate layer (C1, C5), the critic's gaps must not target the wording, and its prompt says to treat text as placeholder. In prose artifacts (C3, C4) the worker may restructure and revise during the loop, but the wording remains placeholder until VOICE.
- ⟨A⟩ *Don't let it veto CUT.* LLM judges have a verbosity bias (Saito et al. 2023).
- ⟨A⟩ **The tell catalog never enters the critic's prompt.** The critic keeps only the article's generic clause about overdone or AI-looking patterns.

**The render, by domain**
| Domain | Fit | Render (what the critic sees) |
|---|---|---|
| UI / visual design | strong | screenshot(s) of the rendered page |
| Presentations | strong | exported slide images (no notes, no outline) |
| Long-form writing | strong | clean text as published |
| ⟨A⟩ Fiction (C6a) | strong (as a ranker) | clean typeset pages among 4+ published passages in the same genre and register; annotations only |
| Marketing copy & ads | moderate | the copy in context (feed mock, inbox preview) |
| Developer experience (CLI/API) | moderate | `--help`, a first-run transcript, README quickstart; no source |
| Research & decision memos | moderate | the report as read; structure only, facts checked elsewhere |
| Synthetic data | moderate | a random sample of records as a table |
| Education | moderate | the lesson as the learner sees it |
| Strategy memos | moderate | the memo as the executive reads it |
| Naming | weak | names shown in use; filter only |

**Wiring.** A loop by definition. Across candidates use `each[ CRITIC ]`; each candidate keeps its own identity because the bar is relative to its own intent. ⟨A⟩ It may wrap ASSET as a worker move. RELAY only after a pick, outside `each[ ]` (port rule 4). In the article, image generation was a *separate* prompt after the loop.

**Reliability caveat.** Evidence on LLM judges of taste comes mostly from older models, and unanchored judges were near chance on UI quality (UIClip: GPT-4V 51.6%) and on prose. Ranking against references aligns better with humans (PairS), but pairwise judgments flip more often under distractor features (35% vs. 9%, Tripathi et al., COLM 2025). **How reliable current frontier critics are is unmeasured.** Hence the ⟨A⟩ calibration step.

**Economics.**
- In the article, the critic produced under 10% of output tokens. The author estimates that a direct redesign by the big model would have cost about 2× and taken much longer.
- Directionally consistent: Anthropic's "advisor strategy" (Apr 2026). Sonnet consulting Opus scored +2.7 pp on SWE-bench Multilingual over Sonnet alone, at 11.9% lower cost than Sonnet alone. But that advisor sees the executor's context, so it is evidence for tiering, not for blind critique.
- Critic cost is dominated by *image input*, so measure cost per candidate on your own runs.

**Evidence.**
- Anthropic, *Building effective agents* (evaluator-optimizer).
- Anthropic, *Harness design* (Mar 2026): a separate evaluator, Playwright screenshots, 5–15 iterations.
- Huang et al. 2023 and Kamoi et al., TACL 2024: self-correction needs external feedback.
- Zheng et al. 2023 and Wang et al. 2023: judge biases.
- Kim et al., *Prometheus*: rubric and reference anchoring.

**Keep from the article.** Self-review isn't objective, so ask *another* agent. The critic sees screenshots only: no code, implementation details, earlier iterations or critiques. Infer the aesthetic, imagine a top studio's execution, outline the biggest gaps, score out of 10. Done only at ≥ 9/10, which is kept out of the critic prompt. The same prompt every time. The bad/OK/great ladder. References as a moodboard. Probe 1–2 iterations. Big critic, capable worker. Each design keeps its own aesthetic.

**Additions ⟨A⟩.** Separate-orchestrator option. The calibration step. Cap = 5. Plateau and best-snapshot re-rank. A GREAT-mode threshold. Up to 10 references. Position shuffle. Different-family critic for prose. The feeling clause. Multi-surface renders. Guards on taste-only, copy, CUT vetoes and the tell catalog.

## ASSET · Specialist Asset
*From T4 "Use image generation to enrich designs." Stage: Deepen.*

**Counters.** Native-medium substitution. Coding agents love to write code, so they fill visual slots with easy code-based alternatives (gradients, shapes, basic patterns), and those are giveaways of AI design. Agents also underuse image tools they already have until told to use them. Anthropic's guidance agrees: current models lean toward reasoning over tool calls and benefit from explicit direction to use specific tools.

**Core move.** When a directed artifact reads as plain, route its key slots to a specialist generator. Integrate the result, combine it with native effects, and verify frame by frame in the real render. Access the generator through credentials that are scoped, spend-limited and never shipped.

**Procedure**
1. **Direction first.** The article's trigger: "the design is pretty plain. Add more personality…"
2. **Find the stand-ins** (code-drawn gradients, shapes, patterns). ⟨A⟩ Pick the 1–3 slots that carry the most personality.
3. **Access route** (article: pick by the agent and subscriptions you have):
   - Codex, Antigravity or Grok Build: the agent's built-in image generation, named explicitly;
   - Claude Code or another agent plus a ChatGPT subscription: the Codex CLI billed to that subscription;
   - otherwise: an OpenAI or Gemini key.
4. **Fence the credentials** (article):
   - a separate key with a tight spend limit;
   - used locally only, never stored in code or the product;
   - if you paste keys often, a gitignored `.env.agents` file plus a note in AGENTS.md / CLAUDE.md that the keys are dev-only.
5. **Instruct:** "consider shaders or 3D effects in combination with images" (article).
6. **Integrate** into the existing direction. ⟨A⟩ Keep copy out of generated images.
7. **Verify frame by frame in the browser** (article). ⟨A⟩ Require file paths and screenshots as evidence.
8. ⟨A⟩ **Prune:** remove assets that add nothing (CUT) or read as a new tell (TELLS).

**Ports.** In: directed `artifact`, `brief`/identity, `cred`. Out: enriched `artifact`, asset files, render evidence, a reusable access setup (RELAY consumes it).

**Knobs.**
- ⟨A⟩ `slots_per_pass`: 1–3.
- ⟨A⟩ `variants_per_slot`: 1 (2–4 if budget allows).
- `compose_with_native`: on (article).
- `verification`: frame by frame in the real render (article).
- `spend_cap`: tight (article).

**Guards**
- *The agent still fakes it.* Name the tool.
- *Fabricated or skipped tool use* (ToolFailBench: Tool-Skip, Result-Ignore, Output-Fabrication). ⟨A⟩ Require files.
- *Key leakage.* AI-assisted commits leaked secrets at 3.2% vs. a 1.5% baseline (GitGuardian 2026). Use the article's key hygiene.
- *Asset fights the direction or becomes a new tell* ⟨A⟩. Run TELLS on assets too.
- ⟨A⟩ **In factual domains, never present generated imagery as evidence.**

**Fit by domain**
| Domain | Fit | Native stand-in → specialist |
|---|---|---|
| UI / visual design | strong | CSS gradients and shapes → generated imagery + shaders/3D (article) |
| Presentations | strong | bullet boxes, drawn rectangles → generated key visuals |
| Marketing creative | strong | headline on a colored block → generated hero image |
| Education | moderate | prose or ASCII explanations → illustrations |
| ⟨A⟩ Explainers, research, demo data | moderate | eyeballed numbers → charts from executed code on real data; toy rows → seeded data. This extends "specialist" from generators to renderers |
| Product ideation | weak | rough storyboard frames only |

**Wiring.** Runs in parallel per variant and per slot, with one integrator per artifact. In the article it is a **follow-up prompt after the critic loop**. ⟨A⟩ It can also be a worker move inside CRITIC. It is nested in RELAY as stage 1.

**Evidence.**
- Anthropic prompting docs (models favor reasoning over tool calls).
- Schick et al., *Toolformer*.
- Shen et al., *HuggingGPT*.

## RELAY · Specialist Relay
*From T5 "For more advanced motion, use video generation." Stage: Deepen.*

**Counters.** The same native-medium substitution as ASSET (motion faked in CSS), plus **one-shot independence**. Separate generator calls share no state, so outputs can't be layered and transitions show seams.

**Core move.** Chain specialist models.
- **Pattern A, Render & Extract.** Generate a looping clip against a solid background, then chroma-key it or use a video-matting model so it can be layered anywhere "without looking like a video." For glass, render over the page's background colors first so the refraction is baked in.
- **Pattern B, Transitions.** Video models interpolate between keyframes. Either generate the clip between two stills, or seed each next clip with the previous clip's final frame so the sequence "continues seamlessly."

**Procedure**
1. **Spot the effect** the agent would fake natively.
2. **One aggregator, one key** (article: fal.ai). The agent finds appropriate recent models for each stage. Name the property you need, with an exemplar ("strong physics and consistency, like Seedance 2.5").
3. **Pattern A** (article):
   - Generate a looping clip on a solid color, or, for refractive subjects, over the destination's own colors.
   - Remove the background with a chroma key, or with a video-matting model for complex cases.
4. **Pattern B:**
   - **B0 Keyframe interpolation** (article): generate both stills (ASSET), then one transition clip between them.
   - **B1 Last-frame relay** (article's suitcase demo): generate still s0 with image generation, then a clip from s0 to state 1. Use that clip's **final frame** to seed the next clip.
   - ⟨A⟩ For chains longer than about 3 segments, keep the exact final frame as the *start* frame and pass the s0 still as an identity reference image only, or switch to B0.
5. **Bind** (article): play on a user action, or scrub frame by frame with a gesture such as scroll or swipe. Match the motion direction to the gesture (vertical for scroll). ⟨A⟩ Implementation tip: for smooth scrubbing, use image sequences or seek-friendly encoding.
6. **Verify frame by frame** in the destination. ⟨A⟩ Re-run only the stage that failed, and keep a manifest (models, prompts, seed frames) so any stage can be swapped later.

**Ports.** In: directed `artifact`, target effect or state list, destination context, interaction model, `cred`, usually an `asset`. Out: layerable `asset`(s), continuous segments (`anchor` handoffs), the integrated `artifact`, ⟨A⟩ the manifest.

**Knobs.**
- `pattern`: A | B0 | B1.
- `render_context`: solid color | destination (article).
- `extraction`: chroma key | matting model (article).
- `anchor_states`: 3 (article demo).
- `playback`: on-action | scrub (article).
- ⟨A⟩ `candidates_per_segment`: 1.

**Guards**
- *Seams.* Seed from the exact final frame (article).
- *Drift on long chains* ⟨A⟩. StreamingT2V shows that naive chaining accumulates hard cuts. Prefer B0 or identity references.
- *Reads as a morph rather than motion* ⟨A⟩. One meaningful change per transition (the Seedance docs).
- *Key fails.* Use a matting model (article).
- ⟨A⟩ *Reduced-motion users.* Provide the anchor stills as a static fallback.
- ⟨A⟩ *Motion as decoration.* Run CUT on it too.

**Fit by domain** (specialist chains only)
| Domain | Fit | Pattern A | Pattern B |
|---|---|---|---|
| UI / visual design | strong | looping hero element | scroll-scrubbed product states |
| Marketing video / ads | strong | product loop keyed once, reused | storyboard beats as one continuous take |
| Education explainers | strong | isolated animated components | multi-stage process the learner scrubs through |
| Audio (music beds, narration) | strong | render dry and solo, or separate stems | each section conditioned on the tail of the last |
| 3D / game assets | moderate | concept on a neutral background → image-to-3D | cutscene states |
| Presentations | moderate | hero object matted across slides | evolving hero across slides, on click |

*Passing text or JSON state between generalist LLM calls has the same `~>` shape, but it is ordinary prompt chaining, not a specialist relay. See 05 §D.*

**Wiring.** Pattern A runs in parallel per element. A Pattern B chain is **strictly sequential**. RELAY nests ASSET as stage 1. In the article it was run by a different agent (GPT-5.6 Sol) on one chosen design.

**Evidence.**
- fal.ai first-last-frame endpoints and its single-key aggregator.
- Seedance 2.5 docs.
- Wang et al., *Generative Inbetweening* (ICLR 2025).
- Henschel et al., *StreamingT2V* (CVPR 2025).
- Robust Video Matting; MatAnyone.

**Keep from the article.** Video models are under-imagined, not under-powered. Use an aggregator: one key, and the agent picks the models. A looping clip on a solid background, chroma-keyed or matted. Glass rendered over the page background first. Keyframe interpolation between stills. The first frame from image generation, with each final frame seeding the next. Play on action or scrub on scroll. One prompt.

**Additions ⟨A⟩.** Identity references for long chains. Candidates per segment. The manifest. The reduced-motion fallback. The scrub-encoding tip. CUT on motion.

## CUT · Subtraction Pass
*From T6 "Cut out elements that don't add value." Stage: Distill.*

**Counters.** The additive default.
- Reward models link length with quality: a length-only reward reproduces most RLHF gains (Singhal et al. 2024).
- On structural puzzles, most models tested chose additive fixes 76–100% of the time. Llama 3.1 70B leaned subtractive on one task, and models *shortened* summaries when asked to revise them (Santagata & De Nobili 2024). So the bias depends on the task.
- GPT-4 added even more when told to "improve" rather than "edit" (Uhler et al.).
- Humans overlook subtraction too, unless the task cues it (Adams et al., *Nature* 2021).
- The article's version: "AI doesn't like to take risks, and it's risky to strip down a design and delete code."

**Core move.** You, the taste owner, look over the work, ask "what really needs to be there?", and push the model with a concrete removal directive. The article's directive had three parts:
- the cuts (gradients, glows, unnecessary containers);
- a structural simplification (an image-centric grid);
- a restraint reference ("truly minimalist… Apple-native").

**Procedure**
1. **Only after a standout direction exists** (article: Deliver begins "once we've gotten to a unique, standout design").
2. **Look at the rendered work** and ask what really needs to be there.
   - ⟨A⟩ Write a one- or two-sentence purpose statement (the article's yardstick: the design "makes sense, flows well, and serves a practical purpose").
   - ⟨A⟩ Run five probes on each element: purpose, redundancy, effort display, overexplanation, custom vs. standard.
3. **Issue the directive** with removal verbs: dial back, get rid of, simplify. ⟨A⟩ Never "improve" or "polish," and allow no new substitutes except standard parts.
4. **Check the result:** opinionated, lets the visuals speak, standard components, text smaller and tighter (article). ⟨A⟩ Compare before and after, run tests if code was deleted, and stop after at most 2 rounds.

**Ports.** In: an `artifact` with an identity, `?H` taste owner. Out: the reduced `artifact`, ⟨A⟩ a cut log.

**Knobs.**
- `taste_owner`: human (article). ⟨A⟩ A fresh-context reviewer is experimental.
- `framing_verbs` ⟨A⟩: removal only.
- `max_rounds` ⟨A⟩: 2.

**Guards**
- *A vague "make it minimal" changes nothing.* The calorie app was *asked* for "clean, minimalist" and still came out cluttered (article), so itemize the cuts.
- *"Improve" framing adds more* ⟨A⟩. Use removal verbs.
- *Over-cutting load-bearing parts* ⟨A⟩. Keep a protected list and run tests.
- *Cutting the identity.* Restraint should make the work *more* opinionated (article).
- *An LLM critic re-adds things* ⟨A⟩. Don't let CRITIC veto removals.
- ⟨A⟩ Lighten CUT for already-compressive tasks such as summaries.

**Fit by domain**
| Domain | Fit | Elements · restraint reference |
|---|---|---|
| UI / visual design | strong | glows, random highlights, redundant labels, custom controls → native components (article) |
| Software engineering | strong | unrequested files, helpers, flags; comments that restate code → standard library; tests as the guard |
| Long-form writing / memos | strong | preambles, recaps, hedges, clever asides |
| Data viz & analysis | strong | Tufte: erase non-data-ink and redundant data-ink |
| Presentations | strong | agenda slides, bullets restating the title (Mayer's redundancy principle) |
| Education | strong | Mayer's coherence principle: tangents, duplicated narration |
| Product scope / PRDs | moderate | DELETE / DEFER / KEEP; the PM is the taste owner |
| Tests / synthetic data | moderate | near-duplicate tests; measure coverage |
| Naming | weak | descriptor bloat |
| Ideation | — | **sits out**: wrong stage |

**Wiring.** ⟨A⟩ Runs in parallel per unit, with one taste owner. Re-run it after any additive block. Default order **CUT → TELLS → VOICE** (inferred from the article's presentation order). Never in Diverge.

**Evidence.**
- Adams et al., *Nature* 2021.
- Santagata & De Nobili 2024.
- Uhler et al.
- Winter et al., *Cognitive Science* 2023.
- Singhal et al., COLM 2024.
- Saito et al. 2023.
- Anthropic prompting docs: models over-engineer, and Opus 5 writes longer documents.
- Mayer (coherence: 10 of 11 tests, median d≈1.32).
- Tufte.
- Apple HIG.

**Keep from the article.** AI loves to add but rarely takes away. Overexplaining is a top sign of AI. Restraint looks premium. Most polishing effort goes into removing things. The calorie-app example (glows, random highlights, labels restating what the photos already show, custom controls → an image-centric grid, native components). The model needs a push from you. Less on screen often communicates more.

**Additions ⟨A⟩.** Purpose statement. Five probes. Removal-verb rule. No new substitutes. Protected list. Round cap. Cut log. Lightening for compressive tasks. Re-runs and the fixed order.

## TELLS · Tell Sweep & Swap
*From T7 "Remove AI tells." Stage: Distill.*

**Counters.** Defaults that every model overuses. A single instance isn't bad, but once users see it in every design it becomes a tell.
- Some slop patterns appear more than 1,000× more often in LLM text than in human text (Paech et al., *Antislop*, ICLR 2026).
- One generation can't see this from the inside, because to the model these are simply its highest-probability choices.
- Banning tells up front backfires (article). Instructions to avoid listed words have limited effect and can backfire (*Antislop*; the pink-elephant effect, Castricato et al. 2024). Anthropic documents bans shifting models to the *next* default (from Inter to Space Grotesk).

**Core move.** While refining, pull up a catalog of overused pattern → better alternative. Look for each pattern, have the AI try alternatives, and keep whichever you like better. **Never ban the catalog's patterns up front.**

**Procedure**
1. **Keep a catalog** of pattern → alternative pairs. The article's four entries for design are below. ⟨A⟩ Keep 5–15 per domain. ⟨A⟩ Grow it by noticing what recurs across independent runs. This extends the article's "Kiln ×4" observation, which it used to show that "be random" fails, into a way of discovering tells.
2. **Generate normally**, with no bans.
3. **While refining**, look for each pattern.
4. **Decide per instance.** Not every gradient, card or label is bad (article). ⟨A⟩ Clusters and prominent placements count; a single buried instance is weak evidence.
5. **Prompt the AI to try the alternative** and keep whichever version you like better (article). ⟨A⟩ One tell per prompt, keep a snapshot, re-sweep once to catch the next default slipping in, and version the catalog by model generation.

**Ports.** In: a near-final `artifact`, `tells` catalog. Out: the revised `artifact`, ⟨A⟩ a hit log, catalog updates.

**Knobs.**
- `enforcement`: audit-and-swap (article). ⟨A⟩ Hard bans only for *objective defects* such as leftover placeholders, lint or type errors, and "As an AI".
- ⟨A⟩ `swap_batch`: 1.
- ⟨A⟩ `resweep`: 1.

**Starter catalogs**
| Domain | Overused pattern → alternative |
|---|---|
| **UI design** (the article's table) | Eyebrow text (small, redundant labels stating the obvious) → remove it (9 times out of 10 you lose nothing) · generic background gradients → background images, patterns or solid colors · **excessive cards and containers → flatter layouts like grids or tiles** · too many fonts, styles and levels → 1–2 fonts and 2–4 styles; accent colors and italics sparingly |
| ⟨A⟩ **Prose (words)** | "It's not X, it's Y" → state Y · reflexive triplets → the real count · puffery ("testament," "pivotal," "tapestry") → a concrete fact · trailing "…, highlighting X" clauses → cut, or make a real causal claim · "serves as / boasts" → "is / has" · restating wrap-ups → end on the last substantive point · dense em dashes → varied punctuation |
| ⟨A⟩ **Prose (structure)** | Identical section skeletons across pieces → vary by content · hook → list → moral arc → lead with the claim · cascades of one-line paragraphs → real paragraphs · headings every two paragraphs → fewer, earned headings |
| ⟨A⟩ **Newsletter / email** | "I hope this finds you well" / "In this issue" preambles → start with the point · a table of contents for three items → cut it · stock sign-offs → plain close |
| ⟨A⟩ **Social / LinkedIn** | A "broetry" hook line → state the point · emoji bullets → plain prose · "Here's what I learned:" lists → one lesson, told · engagement-bait closer ("Agree?") → end on substance |
| ⟨A⟩ **Marketing copy** | Hype verbs (unlock, elevate, seamless) → a plain verb + a specific outcome · staccato negations ("No X. No Y.") → one sentence on what's included · repetition for effect → say it once |
| ⟨A⟩ **Reports & memos** | An exec summary restating the question → lead with the answer · a bolded lead-in on every bullet → prose · "it's important to note" → state the claim · "on the one hand…" with no verdict → make the call |
| ⟨A⟩ **Slides** | The same title + 3 bullets everywhere → vary the layout · 3-up icon grids → one number or image · topic-label titles → assertion titles |
| ⟨A⟩ **Code (style; audit, not lint-ban)** | Comments narrating the code → explain why only · single-use helpers and flags → inline · generic names (data, utils) → domain names · stray summary `.md` files → delete |
| ⟨A⟩ **Lesson plans (structure)** | The same intro → activities → conclusion template whatever the topic → shape the lesson by its objective · remember-level task chains → higher-order tasks |
| ⟨A⟩ **Fiction** (C6a; categories from Chakrabarty, Laban & Wu, CHI 2025) | Clichés and stock imagery ("the air was thick with," "a symphony of") → one concrete detail only this story could have · explained emotion ("she felt a pang of…") and unnecessary exposition → action or subtext · ornate or awkward word choice → the plain, precise word · the tidy epiphany ending ("in that moment, she realized") → end on an image or an action · uniform sentence rhythm and reflexive triplets → varied rhythm · characters who state the theme in dialogue → let it stay under the surface · names, settings or premises that recur across the vanilla runs → choose ones rooted in the story's world |

**Fit by domain** ⟨A⟩
| Domain | Fit | Notes |
|---|---|---|
| UI / visual design | strong | the article's table |
| Fiction | strong | prose clichés and exposition; flag only, the author rewrites (C6a) |
| Prose, marketing copy, reports, slides | strong | catalogs above |
| Code diffs | moderate | many code tells are real defects; style tells are audited, not linted |
| Synthetic data | moderate | tells are statistical (stock names, round numbers); the swap is often programmatic sampling |
| Naming | moderate | names recurring across runs; send back to SEED/VISION |
| Product strategy | weak | the sameness is in the ideas themselves; flag stock ideas, don't reword them |

**Guards**
- *Up-front banning.* Keep the catalog out of generation (article).
- *Blanket removal* creates a new "de-AI'd" signature ⟨A⟩, so triage each hit.
- *Substitution / whack-a-mole* ⟨A⟩: name a concrete alternative and re-sweep once.
- ⟨A⟩ *No tells ≠ good.* The Wikipedia AI-cleanup guide warns that surface signs aren't the problem itself. TELLS is polish, not QA.
- ⟨A⟩ *Self-audit blindness.* Always supply the catalog explicitly.
- *Stale catalog.* Tells drift between model generations (for example, "delve" dropped off sharply in 2025). One targeted model update (OpenAI, Nov 2025) made a stated em-dash ban work, so re-check the catalog on every model change.

**Wiring.** Report-only auditors may run in parallel; swaps run one at a time. **The catalog never enters a generation prompt or the CRITIC's prompt.** Swap actions call CUT (remove) or ASSET (gradient → image).

**Evidence.**
- Paech et al., *Antislop* (ICLR 2026): soft, backtracking suppression keeps quality at 8,000+ banned patterns, while decode-time token banning becomes unusable around 2,000 patterns.
- Castricato et al. 2024.
- Anthropic prompting docs ("tell Claude what to do instead of what not to do").
- Wikipedia, *Signs of AI writing*.
- Kobak et al., *Science Advances* 2025.
- LLM-generated Java: 63% more code smells than reference solutions (2025).
- TechCrunch, Nov 2025.

**Keep from the article.** Every model overuses certain patterns, and they become tells through ubiquity. Know both the patterns and the alternatives. Be intentional rather than banning as a blanket rule. The four-row design table. Don't ban from the get-go; it makes the model overthink and produce stranger patterns. While refining, pull up the list, prompt alternatives, and compare.

**Additions ⟨A⟩.** Non-design catalogs. Recurrence-based discovery. Triage threshold. One swap per prompt. Re-sweep. Catalog versioning. The objective-defect hard-ban carve-out. The polish-not-QA and self-audit guards. The fit table.

## VOICE · Human Voice Pass
*From T8 "Rewrite copy by hand." Stage: Distill.*

**Counters.** Every word slot gets filled with the most typical phrasing, and models "love to add," so there is more of it: clever hooks, metaphors, lines repeated for effect. Every user samples from the same narrowed distribution, which produces one shared, recognizable AI voice. The model also lacks the owner's real voice.

**Core move.** Treat AI-written copy like **lorem ipsum**: it helps you see the structure, but it's a placeholder. **A human reads each line of copy and rephrases it in a consistent voice.**

**Procedure**
1. **Treat model copy as a placeholder** (article). ⟨A⟩ Tag it `COPY-PLACEHOLDER` so none ships unreviewed.
2. ⟨A⟩ **Run last**, after CUT and TELLS, so nobody polishes text that is about to be deleted (or as the lane after CUT, see Wiring).
3. ⟨A⟩ **Extract a copy deck:** the agent lists every reader-facing string with its purpose and length budget, and proposes no wording.
4. **Set the one voice** (article: "a consistent voice"). ⟨A⟩ Write 3–5 attributes and 2–3 sample lines.
5. **Rewrite every line by hand** (article). Keep lines that already work; the database-tool example kept its tagline. The human version is usually shorter, simpler and less eyeroll-inducing.
6. ⟨A⟩ **Owner sign-off.** The human writes only claims they personally stand behind. *This is not fact verification* (that's the VERIFY candidate in 05).
7. ⟨A⟩ **Apply verbatim and lock.** The agent inserts the human copy exactly and may *flag* problems (layout breaks, leftover placeholders) but never rewrites.
8. ⟨A⟩ **Skim test:** read only the headings and first lines; the point and the next step should land.

**Ports.** In: a structurally stable `artifact` with placeholder copy, `?H` (the accountable human), the owner's facts. Out: an `artifact` with human copy, ⟨A⟩ a copy deck, the voice reference.

**Knobs.**
- `scope`: every reader-facing line (article). ⟨A⟩ Priority order: headline, primary claim, CTA, error/empty states, then the rest.
- `rewrite_depth`: every line; never spot-check.
- ⟨A⟩ `ai_role`: scaffold, apply, flag.
- `length_target`: usually shorter than the draft (article).
- ⟨A⟩ `lock`: on.

**Guards**
- *Delegating back to the model* ("make it sound human") just produces another sample from the same distribution. A majority vote of heavy-LLM-user readers still caught humanized text; individual experts were less reliable (Russell et al., ACL 2025).
- *Mistaking tell-scrubbing for rewriting.* The after-version must say the point **more plainly and more briefly in the owner's voice** (article: shorter, simpler). Removing a few tells is not enough.
- *Human cleverness replacing AI cleverness* ⟨A⟩. Use the skim test.
- ⟨A⟩ *Mixed voice.* In mixed sets, the suspected-AI lines are trusted less (Jakesch et al. 2019).
- *Later passes overwrite the copy* ⟨A⟩. Lock it.
- **Ghostwriting:** if the human doing VOICE isn't the byline owner, every first-person anecdote, number and opinion needs the owner's approval. No invented experiences.

**Voice surfaces, by domain**
| Domain | Fit | Surfaces the human owns |
|---|---|---|
| UI / product design | strong | every visible string (article) |
| Marketing & launch comms | strong | hook, claims, CTA in one voice across channels |
| Research & analysis | strong | title, abstract, findings, conclusions, limitations |
| Workplace communication | strong | every sentence the recipient will attribute to you. Exception: transactional text, where the disclosed-AI trust penalty is small (Purcell et al., *iScience* 2025) |
| Presentations | strong | slide titles as spoken claims; opening and closing lines |
| Software engineering | moderate | error messages, empty states, CLI output, release notes, PR "why"; routine commit messages can stay AI-written |
| Education | moderate | feedback on student work, announcements |
| Naming & brand | moderate | tagline, about page, founder story |
| Synthetic data | weak | dashboard headlines and chart titles only |

**Wiring.** The last step of Distill. Agent sub-steps can run in parallel. ⟨A⟩ **Never let the AI merge parallel human rewrites.** ⟨A⟩ VOICE may run as a lane beside non-copy visual TELLS only *after* CUT and the copy-bearing tells (e.g. eyebrow text) are done: `CUT > TELLS(copy-bearing) > { TELLS(non-copy visual) | VOICE }`.

**Evidence.**
- Russell, Karpinska & Iyyer, ACL 2025: the majority vote of five heavy-LLM-user annotators misclassified 1 of 300 articles, including paraphrased and humanized ones. Individual experts were less reliable.
- Padmakumar & He, ICLR 2024: the homogenization came from the model-contributed text.
- Schilke & Reimann 2025: disclosure lowers trust.
- Jakesch et al. 2019, 2023.
- BetterUp & Stanford: "workslop."
- Morkes & Nielsen: concise + scannable + objective writing gave a 124% usability gain.

**Keep from the article.** The copy may matter most for whether a design reads as tasteful or slop. AI copy is lorem ipsum. A human reads **each** line and rephrases it in a **consistent** voice. The database-tool example: the same tagline, then plain statements of what it is, what it does, privacy, time-to-value and the CTA. The human version is almost always shorter.

**Additions ⟨A⟩.** Placeholder tag. Run-last rule. Copy deck. Voice attributes. Owner sign-off. Lock. Skim test. Ghostwriting rule. Mixed-voice guard. No AI merging. Lane option.
