# Architecture Decision Records

Every architectural decision behind the Off-Center protocol, its testing harness, the research program and the product track, recorded at the user's request on 2026-10-06 ([ADR-0001](0001-record-architecture-decisions-as-adrs.md)). Earlier decisions were back-filled from the conversation record, the protocol files and the research reports, then checked against those sources by separate AI verification passes. These passes ran on Claude, the same model family that drafted the records (and the same family as the studies' worker and critic), so they are not independent human review.

## How to read this log

- **Status:** *Accepted* decisions are in force; *Proposed* ones are recommendations awaiting the user's decision. A row's "changed by" links name the later records that change an Accepted one (it is never edited); read them together.
- **Decided by** says who made the call, honestly: **User** (the user directed it), **User-approved** (Claude recommended, the user explicitly chose it), **By continuation ⚑** (Claude proposed it in delivered work and the user built on it without explicit approval; these need ratification), **Delegated** (Claude decided under authority the user delegated, e.g. "Let's code"; reversible and flagged for review) and **Pending**.
- Dates are local (UTC−7). Evidence links point to the [conversation record](evidence/conversation.md) and the rest of the [decision evidence](evidence/README.md) kept in the repository, the [protocol files](../../protocol/) and the research reports under [docs/research](../research/).
- New decisions get the next number. A changed decision is not edited in place: a new ADR supersedes it.
- A record's Context and Decision are final once it reaches main's first-parent history as Accepted. The commit that accepts a Proposed record may finalise its Decision. Branches merge with `--no-ff`, so a branch's own commits are drafts. A record that changes an Accepted one reaches main in the same commit as its "changed by" link: add the index row and the links on the branch before merging, or merge with `git merge --no-ff --no-commit <branch>` and add them before committing. Main's history is not rewritten (the "Protect main" ruleset blocks force-pushes), so a breach that reaches main is named in the test with its reason. `scripts/test/adr-records.test.ts` checks this against git history ([ADR-0103](0103-adr-log-rule-and-ci.md)): it fails an edited Context or Decision, a "changed by" link that reaches main after the record it names (from ADR-0103 on), and a breach on main that is not named. It cannot see a missing link, because no record says, in a form a test can read, which records it changes; adding the links is the author's job. It sees a fast-forward only through the edits that then show up on main.

**112 records:** 105 accepted (15 of them by continuation, awaiting ratification; 38 delegated) and 7 proposed. ADR-0044 to ADR-0057 are the credibility charter (CR1–CR14).
