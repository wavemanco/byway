## Context

Code generated by agents is untrusted, and screenshots must be comparable across conditions. Claude estimated that this machine fits about 5–7 sandboxes at once, so roughly 1,700 confirmatory pages would take weeks locally but about a day in the cloud.

## Decision

Each candidate is generated in its own hardened local Docker container. Screenshots come from a separate, version-pinned renderer. Local Docker is used for development and pilots. Cloud sandboxes are used only for the big confirmatory generation batch.

## Alternatives considered

- **Docker + gVisor (runsc)** — Much smaller attack surface. But up to 10–200x slower on file-I/O-heavy work such as npm installs and builds, and not installed.
- **Docker Sandboxes (sbx microVMs)** — A microVM per sandbox, with credential injection through a proxy. Orchestrating them at scale from a backend is unproven, and it needs Windows Hypervisor Platform.
- **Vercel Sandbox as the default backend** — Firecracker microVMs, 24 h sessions and high concurrency. Cloud-only and pay-per-use, and data leaves the machine.
- **E2B, or Inspect's k8s, Modal or Daytona providers** — Options for scaling out. They need extra accounts and infrastructure, and self-hosting E2B is complex.
- **Run everything locally, including the confirmatory batch** — No cloud cost and no data leaving the machine, but weeks of wall-clock time for the confirmatory study.

## Consequences

**Positive**

- Untrusted generated code is isolated, and screenshots are comparable across conditions.
- The confirmatory batch of about 1,700 pages takes about a day in the cloud instead of weeks locally.

**Negative**

- Two execution backends can introduce a backend effect unless it is controlled.
- Cloud runs send data off the machine and add cost.

**Follow-ups**

- The architecture digest proposes specific hardening, not yet decided. Sandboxes would drop all capabilities and run with no-new-privileges, a read-only root, a non-root user and resource caps. They would have no network except a Unix socket to the gateway and to a pinned npm registry mirror. The renderer would be a pinned Playwright image recorded by digest, with fixed viewports and a frozen static export.
- Choose the cloud sandbox provider. r_arch suggests Vercel Sandbox Pro at about $0.22 per candidate-hour.
- Decide the sandbox network policy: open internet, as in the article, or a pinned package-registry mirror.
- Either run the confirmatory study on one backend, or balance backends across conditions and record the backend as a covariate.
- Raise the WSL memory cap if needed.
