*This design is for you to read before W is built. It was read against main at a002e60 on 2026-10-22, and nothing was changed. ## What changes and why

Today every step the engine schedules is handed the whole run by value:
- the brief, with all its attachments (`RunRef.problem`, copied into each step at interpreter.ts:141-144);
- every SEED string handed out so far (`RunRef.seeds`);
- the fixed copy deck and every VOICE answer (`ports.voice`, `ports.held`);
- your own tell catalog, which goes to every model step.

Start accepts 20,000 characters plus five attachments of 200,000 each. That is about 1 million characters, or about 3 MB of Chinese or Japanese. Temporal refuses one value over 2 MB and one scheduling batch over 4 MB. So a large brief, copied into a fan-out, can leave a run stuck in "running" with nothing spent (F02; ADR-0098's Negative). W stores what you bring once and passes short ids instead.

## What is stored where, and how it is read

| What | Today | After W |
|---|---|---|
| The brief (text, fields, attachments) | In the workflow's start input and in every step's input | One JSON file in the content-addressed store, written by Runner.start before the workflow starts. The start input and every step carry its id. A step that fills the problem slot reads it once (ArtifactReader). |
| Fixed copy deck, the author's draft, your own tell catalog | By value. The tells go into every model step's input. | Text files written at start, with ids in the start input. The deck's id is the first `ports.voice`. **(Claude:** the rows name the brief and the deck. The draft and the tells are the same kind of input, so they move too.**)** |
| SEED strings | Every seed so far, in every step's input | Not sent. Each seed is already kept as a memo. A step that writes reads the run's seeds from the store, through one new read-only Store method on the existing memo table (no migration). The seed's memo key gets a prefix so the seeds sit in one key range. |
| VOICE answers | Text, in every later step's input | finishHumanStep stores the answer as a text file and returns its id. `ports.voice` and `ports.held` hold ids, and the keepsVoice check and the voice slot read the texts. |
| refs, the recipe, checkpoint answers | ids; the recipe by value (at most 1 MiB, or 32 KiB when composed); each answer once | Unchanged |

What else this means:
- StartRunInput (what the web app, the CLI and the tests call) does not change. The run record does not change either.
- PR3 now sees a superset of today's seeds: a sibling's seed, or an earlier attempt's. The check gets stricter, never looser.
- If a file is missing after a partial restore, the step fails with a plain message. The start-up data check already lists missing files.
- The batch bound loses its seed term, because seeds no longer travel, and limits-batch.test.ts measures it again. A recipe refused today only for its seeds would now be admitted. No catalog verdict changes. The 2 MiB engine bound stays as it is. **(Claude)**
- Not in W: P2's third part, handing each step only the ports it reads (open choice 3).

**What still travels by value:** text the models write, and your reactions in the brief, taste and critique ports. The answer route caps each reaction at 100,000 characters. In the catalog, the widest fan-out after one is three branches (C5's concepts, C6's audit), so at most about 0.9 MB. A composed recipe could run 32 steps in parallel after one. W's record files this as a new row.

## VOICE-RETRY: the interpreter's fix (D9)

**Today:** when C5's launch gate fails, the run goes back into D2 with the ports D2 started with (interpreter.ts:159-179). The second late VOICE then offers the AI's copy again. If you send it back unchanged, the AI's copy ships.

**After W:**
- The interpreter keeps the id of each VOICE's last answer and of the deck it answered, and carries both across the retry.
- When that VOICE runs again because the gate sent the run back, the box starts from your earlier lines wherever they still fit the work:
  - for a deck of named fields (C5's headline, tagline and captions), when your lines still read as an answer to the work's deck;
  - for prose, only when the deck has not changed.
- If they do not fit, the box starts from the work's lines, and the question says your earlier lines could not be kept and quotes them.

**(Claude)** Two details:
- The "unchanged" check compares your answer with the work's own deck, not with what the box started from. Otherwise sending your earlier lines back would write nothing.
- On a web page the question names your earlier lines but never pre-fills them, because a page's lines are read again from the browser. No catalog recipe reaches this case, since C5 has the only gate.

## Tests (no wall-clock assertions)

## Choices still open

- **Row 104: when you decline an optional critique step (a cut or a check), what happens to the writer after it, which today acts on an older critique?**
  - Clear the critique (Recommended): a declined step that would have written the critique leaves it empty and marked, so the writer after it makes no change and its step says why, by the same path as an empty CUT ("Nothing to remove")
  - Skip the writer: the step after a declined critique step is shown as skipped, with why
  - Leave it parked on its other trigger (before composed recipes go to anyone besides you)
  - *Recommendation:* Clear the critique (Recommended) — It reuses the mechanism the interpreter and @byway/recipe's semantics already have for an empty critique, so no new rule is needed to say which writer belongs to which critique. Skipping the writer needs that rule, and composed recipes can blur it. No catalog recipe reaches the case: C4's optional wraps its writer, and C6a's final read has no writer after it. - **Content-layer pilot (row 120): its trigger "a workflow change is made for another reason" literally covers W. Does W start the pilot?**

  - Yes, by the literal trigger or by the audit's wording ("a change to VOICE or the page workflow", which VOICE-RETRY meets): the pilot, about 5 real C1 runs at roughly $6-30 on Balanced by byway's own estimate, runs after your first live runs, and its counts decide the content-layer question

- **P2's third part, "activities receive only the ports their step reads" (row 76): build it in W, or leave it on its row?**
  - Leave it on its row (Recommended): W moves the brief and your inputs, the seeds and the held voice. Handing each step only its ports is picked up when the engine's limits are raised or when a recipe meets the batch bound
  - Build it in W: each step is handed only the ports it reads, through an accessor that refuses a port it was not handed, so a gap fails loudly. About one more day, touching every activity
  - *Recommendation:* Leave it on its row (Recommended) — After W, the only things that still travel by value in bulk scale with the recipe's shape (option lists and views). So the change buys headroom, not a fix. Its risk is a step silently missing a port it reads, your held words included, just before your first spend. The row as written includes it, so leaving it out changes the batch's contents, which makes it your call.
- **Long-context rates: after W, a very large brief runs where today it hits Temporal's limits and spends nothing. A call above Google's 200K-token tier would be reserved and recorded at $2/$12 instead of $4/$18, so real spend could pass the cap. What should W do about it?**
  - Leave it to batch 0's row (Recommended): the row "Rates byway does not record, and a maximal brief passes Google's 200K tier" keeps its trigger (large attachments, other users), and W's record adds that briefs this large now run
  - Price the tiers in W: prices.ts gains the long-context rates (OpenAI above 272K input tokens, Google above 200K), and the gateway prices each call at its tier
  - Refuse such briefs on live runs: Start refuses a brief whose prompt would pass the smallest long-context tier of the run's profile
  - *Recommendation:* Leave it to batch 0's row (Recommended) — Reaching the tier takes roughly 800,000 characters of English, or roughly 200,000 of Chinese or Japanese, in one prompt, and your first runs use small briefs. Pricing by tier is money-path work with its own check (ADR-0109's area) and is better done when its row fires than folded into W.
