On 2026-10-22 you answered D2 with "Build a true stop now" (not the recommended option), and the designs with "Yes, short designs first (Recommended)". Nothing below is built until you say yes. ## What the person sees

- **The question** (RunScreen.tsx). Today it reads "Cancel this run? What it made so far is kept." Proposed: "Cancel this run? What it made so far is kept. An AI call already under way may still be paid for: byway cuts it off where the provider allows, and otherwise the run stops when it returns."
  - The buttons stay "Cancel run" and "Keep going".
  - The group gets the question as its description (aria-describedby, as ConfirmPanel.tsx does), so a screen reader reads all of it. The D2 check of 2026-10-18 noted this gap.
- **Afterwards.** A run reaches Cancelled only once its steps in flight have ended, because the activity proxies use Temporal's default cancellation type. Today that means waiting until the call returns, which can take minutes for a long build or a clip. When byway cuts the call off, it takes a few seconds. The Cancelled panel adds: "If byway cut off an AI call, Settings lists it under Spending records until you clear it."
- **Settings.** A cut-off call is listed with the calls that may have been billed. The words for its reason become: "byway stopped waiting for {provider}'s answer (its run was cancelled, byway stopped, or it lost its connection), so it never learned the cost."

## What cuts a call off, and how

**When.** Only the person's Cancel or the run ending cuts a call off (the audit's default, kept). Temporal's cancel reaches the step in a heartbeat reply about 2 s after Cancel, and it carries a reason:
- `CANCELLED` means the workflow cancelled its one scope (run.ts). It does that only on Cancel, on "Stop the run" and on a failure, so the run is ending and the call is cut off.
- Any other reason (a timeout, a lost or stopping worker, a closed workflow) cuts the call off only if the store already shows the run ended. Otherwise nothing changes: another attempt takes the call over (ADR-0099), or byway's close hands it back.

**How.** liveness.ts makes a `stop` signal from that rule. The activity wrapper adds it to the step's `operation`, beside `until` and `cancel`. `operation` is joined after the request is hashed, so memo keys do not change. The gateway hands `stop` to the adapters that can use it, and copies it onto a decline's retry.

**Provider by provider:**
- **Every provider:** once `stop` fires, nothing is sent again, and the retry wait ends at once. Today a call whose attempt failed can be sent again after Cancel, because errors.ts reads an abort as a "maybe" that can be retried.
- **Anthropic (streamed):** the stream is aborted through the SDK's `signal`. Anthropic's streaming page does not say what a closed stream bills. Third parties report the input billed in full and the output up to the cut, so the saving is likely but not documented.
- **fal (queue jobs):** byway sends fal's queue cancel for the job under way, and submits nothing more (no last-frame job). It sends the cancel over REST, as it does the submission, because the SDK's cancel resolves the same way whether fal removed the job or only asked it to stop.
- **OpenRouter, OpenAI and Google are not cut off.** byway's OpenRouter calls (all pinned to Anthropic) and its OpenAI calls are not streamed. OpenRouter says that if such a request is aborted, "you will be billed for the complete response". Google's SDK says its abort is client-only and still charged. Cutting these calls off would save nothing and would lose the exact cost.
- **The demo's mock** is cut off like Anthropic, so the demo and the tests take the same path. It reserves $0, so a cut-off mock call counts nothing.

## What byway records for a cut-off call, and why

- **No ledger entry,** since no answer came to settle. The spend book's row becomes "may have been billed" at its reservation. It counts against the workspace only until it is cleared in Settings (ADR-0095).
- **Its reason is "interrupted".** The book's abandon gains a reason. The existing CHECK already allows "interrupted", so the schema does not change.
- **Exceptions:**
  - Nothing billable was sent yet: the row is released and counts nothing.
  - fal answers 200: the job was removed and never processed, so it counts nothing (Claude's reading of fal's docs).
  - fal answers 400, already completed: the clip was made, so it is settled at its seconds and price, through today's "made the clip and billed it" path, without downloading it.
  - fal answers 202, or the cancel fails: the call may have been billed, and it is listed with the job's request id, which is already recorded.
- **Partial usage (correction to the audit's default).** The default said to record a cut-off call from the stream's partial usage where the provider reported it. Checked against the docs, that never applies:
  - Anthropic's first event gives the input, but the output count comes in `message_delta`, which Anthropic's examples send at the end.
  - OpenRouter reports usage only in a stream's last chunk.
  - byway's other calls are not streamed.
- **Claude proposes dropping that half of the default** (choice 2). A partial count would understate the bill, and it would take the call off the list you check against the provider's dashboard.

## What stays as today, and why

- **Calls that finish:** OpenAI, OpenRouter and Google calls, and every image call, finish and are settled at their true cost. For those, the run reaches Cancelled when the call returns.
- **No cut-off:** timeouts, lost or stopping workers, and Pause cut nothing off, so a paid answer stays for the step's next attempt.
- **The advisor's calls** are untouched: they belong to no run, so no Cancel reaches them.
- **New calls after Cancel** are refused, as now.
- **The memo** keeps nothing from a cut-off call, since its run has ended.
- **Unchanged records:** the ledger format, the spend book's schema, the caps and Clear.

## Tests

No test asserts on the clock: each fake answers only when its signal aborts, and each wait is on a condition.

1. **Anthropic:** a fake stream held until it is aborted. Then: one request was sent and none again, no ledger entry, and the row is "interrupted" at its reservation.
2. **The retry wait:** a stop during it means the next attempt is never sent.
3. **Calls not cut off:** OpenAI, OpenRouter, Google and image adapters get no signal, and a call stopped mid-way is settled as today.
4. **fal:** a stop while polling sends one cancel with the request id. A 200 is released; a 202 is uncertain with its jobs; a 400 is settled at its seconds with no frame job; a failed cancel is uncertain.
5. **The stop rule:** `CANCELLED` aborts. `TIMED_OUT` with the run going does not. `NOT_FOUND` with the run ended does.
6. **Memo keys** are unchanged when `stop` is set.
7. **A source check** that the workflow has one cancellation scope.
8. **Through the real workflow:** liveness.test.ts's Cancel test is rewritten without its `sleep(2_500)`. ## Size and risks

**Size: M.** About a day of work, plus one adversarial check and one CI cycle shared with batch B. That makes batch B M-L, as the audit said.

**Risks:**
- Anthropic may bill a cut-off answer in full. Then Cancel saves nothing there, and the cost is only estimated.
- A reservation plans the full output allowance, so it can be well above the bill, and it holds workspace headroom until cleared.
- Reading `CANCELLED` as the run ending holds only while the workflow has one cancellation scope.
- A job fal is already running may still finish (its 202 answer).
- An answer that finishes at the moment the stop fires is thrown away and counted at its reservation.
