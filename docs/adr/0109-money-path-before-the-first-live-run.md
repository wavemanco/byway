## Context

The owner's first live run (backlog "First live run with real keys and real money") is the first time byway spends real money. Its row asks for the model ids and their price rows, last read on 2026-10-07, to be read again first. The backlog also named six places where what the person is told about money was not true, or where a paid run could fail after its earlier steps were paid for:

- **A Gemini image's thinking.** Balanced takes its images from `gemini-nano-banana-2.1`. `providers/google.ts` charged an image answer per image plus its prompt and ignored `thoughtsTokenCount` and the answer's text ([ADR-0091](0091-provider-edge-billing-fixes.md) Consequences: "Gemini image thinking tokens are not counted").
- **A run start that timed out.** `start-failure.ts` read gRPC 4 (DEADLINE_EXCEEDED) like 14 (UNAVAILABLE), as the engine being down. A Start whose reply timed out after Temporal accepted it was marked failed with "byway's run engine was not running, so this run did not start. Nothing was spent.", though its workflow could run, and a call already under way when the run read failed would still be charged. The same code holds [ADR-0099](0099-paid-operations-keyed-to-their-caller.md)'s second double fault: of two deliveries of one Start to a stopping engine, the one that wrote the run marked it failed when its own start failed, even if the other delivery's start went through.
- **The secrets file's names on a lowercase-drive start** ([ADR-0100](0100-corrections-found-by-the-final-re-check.md) item 6). The names `.env.agents` listed were kept in a map of the env module's own. A Windows start from a current directory whose drive letter is lowercase loads that module twice (`scripts/serve.ts` by path, `file:///c:/…`; `pages.ts` through `@byway/gateway`, `file:///C:/…`), so the renderer's copy knew no names and Chromium got the file's names that do not look secret. Provider keys and secret-looking names were still left out.
- **VOICE in the estimate.** `estimate.ts` counted one mid-tier `voice.apply` completion for each VOICE that writes the work, though VOICE makes no model call ([ADR-0081](0081-voice-writes-the-persons-copy-exactly.md)). That overcount would have gone into the first live run's comparison of estimates with the ledger.
- **A model RELAY step outside a media recipe.** The composed profile admitted one. It cannot run there (`storyboardShots` reads a storyboard, which only a media recipe's work is), so it fails when reached, after the steps before it were paid for, while its explainer promises "one clip of the last shot".
- **Billing assumptions no documentation backs.** `errors.ts` treats a provider-bodied 5xx and a mid-stream error event as unbilled, which permits one blind re-send ([ADR-0091](0091-provider-edge-billing-fixes.md), [ADR-0095](0095-paid-calls-have-a-durable-spend-book.md)). [ADR-0102](0102-one-refusal-rule-for-every-provider.md) records OpenAI's image moderation block at no cost. The block's error codes came from community reports.

What the providers' own documentation said on 2026-10-18, read with no keys and no paid calls (the pages are listed under Evidence):

- **Every model id the profiles name is listed.** Anthropic: `claude-fable-5-1`, `claude-opus-5-5` and `claude-sonnet-5-5`, current models, each retired not sooner than September 2027. OpenAI: `gpt-6-astra`, `gpt-6.1-sol`, `gpt-image-2.5-flare` and `gpt-image-2.5-sunburst`, none deprecated. Google: `gemini-3.8-flash` and `gemini-nano-banana-2.1` are stable; `gemini-3.1-pro-preview` is listed with no status, not among the deprecated models. OpenRouter: `anthropic/claude-fable-5.1`, `anthropic/claude-opus-5.5` and `anthropic/claude-sonnet-5.5`. fal: both Kling endpoints and `ffmpeg-api/extract-frame`.
- **Every figure byway recorded matched its page but two, and the OpenAI rows lacked a rate their page lists.**
  - `claude-sonnet-5-5`'s cache hits are $0.10 per 1M tokens. On 2026-10-07 the table said $0.20 and its prose $0.10, and byway kept the higher figure; now the table, its footnote ("0.05x the base input price") and the prose agree.
  - `gemini-nano-banana-2.1`'s output is priced two ways: $7.50 per 1M tokens "for text and thinking" and $30 per 1M for images, which Google gives as $0.0336 for a 1K image (1,120 tokens). Google's image guide says thinking is on for its Gemini 3 image models and cannot be turned off (this model's default level is medium), that thinking tokens are billed by default for thinking models, and that the interim "thought images" are not charged. Neither page gives a count of thinking tokens per image.
  - OpenAI's cache writes. The pricing page lists a 30-minute cache-write rate ("Short context 30m write") for each OpenAI text model byway prices: `gpt-6-astra` $12.50, `gpt-6.1-sol` $2.50 and `gpt-6-luna` $0.125 per 1M tokens, 1.25× their input. byway's rows had no such rate, and `providers/openai.ts` did not read `prompt_tokens_details.cache_write_tokens`, so a written token was charged at the input rate, a fifth below its cost. The 2026-10-18 reading did not record it; the installed SDK, in the lockfile since 2026-10-07, already has the field, though the page as it stood on 2026-10-18 was not kept. The check of B1 found it (MONEY-1), and the page and OpenAI's prompt-caching guide were read again on 2026-10-21. The guide says caching "is enabled by default for supported OpenAI models", and that for GPT-5.6 and later "cache writes cost 1.25× the standard, uncached input-token rate" for the default 30-minute lifetime.
- **Failed requests.** Only fal says: "Server errors (HTTP 500+) are never charged." Anthropic's errors page, OpenAI's error-code and pricing pages, Google's troubleshooting and pricing pages, and OpenRouter's errors page say nothing about whether a failed request is billed. OpenRouter says an answer with no content may still be charged for its prompt by the upstream provider; that answer is a 200 with its usage, which byway ledgers.
- **OpenAI's moderation block.** The image guide now documents `moderation_blocked`, with `error.type` "image_generation_user_error" and an optional `error.moderation_details` whose `moderation_stage` is `input`, `output` or `unknown`. It names neither `content_policy_violation` nor an HTTP status. Neither it nor the pricing and error-code pages say whether a block is billed.

## Decision

1. **Prices and ids, read again.** Every row in `packages/gateway/src/prices.ts` and the id list in `profiles.ts` name their 2026-10-18 reading; the OpenAI and Google rows also name a reading on 2026-10-21. `claude-sonnet-5-5`'s cache hits are $0.10 per 1M tokens. The three OpenAI text rows record their 30-minute cache-write rate ($12.50, $2.50 and $0.125 per 1M tokens), and `providers/openai.ts` reads `cache_write_tokens`, so a written token is charged at that rate. Reads, writes and the rest of the prompt are each charged once, as OpenAI's guide counts them. Every other figure is unchanged. The rates byway does not record are named in the comments, with the way leaving each out leans:
   - **High.** Google's context-cache rates (`gemini-3.1-pro-preview` $0.20; `gemini-3.8-flash` $0.075, then $0.15 from 2027-01-01) and `gpt-6-luna`'s cached input ($0.01): a cache hit is charged at the input rate. Google's implicit caching is on by default for these models; no profile uses `gpt-6-luna`.
   - **None today.** OpenRouter's cache rates (reads at 0.05× input, 0.025× for Fable; writes at 1.25× for five minutes and 2× for an hour): Anthropic caches only when a request carries `cache_control`, which byway never sends, and the gateway records the cost OpenRouter reports (`usage.cost`) rather than pricing the tokens. Were that cost missing, a read would lean high and a write low. The gpt-image models' cached text input ($1.25) applies only to images made through the Responses API; byway uses the Images API.
   - **Low, for requests byway does not make.** OpenAI's 12-hour cache writes (2.5×, Responses API only), OpenAI's long-context rates (over 272K input tokens) and Google's (prompts over 200K), OpenAI's 10% regional-processing uplift, and Anthropic's 1-hour cache writes, `inference_geo: "us"` multiplier (1.1×) and fast mode. Google's cache storage price applies only to explicit caches, which byway does not make.
2. **A Gemini image's text and thinking are charged.** `gemini-nano-banana-2.1`'s row charges $7.50 per 1M output tokens on top of $0.0336 an image. As an image answer's output tokens, `google.ts` reports its `thoughtsTokenCount` plus the answer's text-rate tokens. Google's reference counts thinking apart from the answer: totalTokenCount is "prompt + tool-use prompt + thoughts + response candidates". The answer's text-rate tokens are the larger of its tokens of every modality but IMAGE (`candidatesTokensDetails`) and `candidatesTokenCount` less its IMAGE tokens, so answer tokens the breakdown does not list are charged at the text rate (since the check of B1, MONEY-2; before, they were charged nothing). The image's own tokens stay priced per image. An answer without that breakdown, or with an empty one, has every answer token counted at the text rate, the image's included, so its cost leans high. The pre-call estimate plans 2,000 such tokens an image (about $0.015): Claude's planning number, since Google gives no count.
3. **A failed run start asks Temporal before the run is marked failed.** When a new run's workflow start fails (a named run's "already started" is still the run's own workflow, as before), the Runner client describes the run's workflow first:
   - **Temporal has it.** The start reached Temporal after all, or another delivery's did. The run is left to its workflow, and the start returns the run.
   - **Temporal has none.** The run did not start. After a timeout its error is "byway's run engine did not answer in time, so this run did not start. Nothing was spent. Start it again."; after any other failure, the words it had before.
   - **byway could not ask.** The run is failed, so the gateway refuses its next calls. Its error says byway cannot tell whether it started, that it makes no new AI calls now, and that one already under way may still be charged and shows on the run; after a timeout it opens "byway's run engine did not answer in time".
   - gRPC 4 is no longer read as the engine being down. gRPC 14 and a refused or reset connection keep "byway's run engine was not running, so this run did not start. Nothing was spent. Restart byway and start it again." apps/web's 503, which a timeout of any engine call can cause, says the engine "is not running, or did not answer in time".
   - The describe is a second call to Temporal, made only after a start that failed. With the engine down it adds about 20 s to the wait for the answer (Negative).
4. **The secrets file's names are kept once per process.** `loadEnvFile`'s record of the names `.env.agents` listed lives on `globalThis` under a registered symbol (`Symbol.for('byway.gateway.env-file-names')`), so every copy of the gateway's env module reads the same names. [ADR-0084](0084-renderer-launch-without-secrets.md)'s sentences on the renderer's environment hold on every start again, whatever the drive letter's case.
5. **A VOICE in the estimate is the person's time only.** The `voice.apply` term and its token assumption are gone from `packages/advisor/src/estimate.ts`.
6. **COMPOSED-MEDIUM.** The composed profile refuses a model RELAY step, and a relay chain, in a recipe whose medium is not `media`, and says why. The composer gets it back as a violation to repair, and re-admission at start ([ADR-0092](0092-recipe-semantics-derived-from-execution.md) decision 5) refuses a stored one. A compositing step (RELAY by a tool), which v1 skips in any medium, stays allowed.
7. **The billing assumptions stay, and say so.** For Anthropic, OpenAI, Google and OpenRouter, treating a provider-bodied 5xx and a mid-stream error event as unbilled stays an assumption; fal documents it, and its queue jobs are never sent blind again anyway. OpenAI's moderation block stays recorded at no cost; its error body, stored as the decline's response and named by hash in its ledger entry, holds the documented `moderation_stage`, so a block at the output stage can be found. The comments in `errors.ts` and `providers/openai.ts` say what the documentation says and does not, with the pages and the date. The first live runs' ledger, against each provider's usage records, is what can settle them (backlog).

## Alternatives considered

- **Read gRPC 4 as "unknown" without asking Temporal** (the backlog's simpler form). Not taken: a run whose workflow Temporal had accepted would still be marked failed, and would then run with its calls refused. Describing first leaves it to its workflow, and with the same code narrows ADR-0099's second double fault: it is closed when the other delivery's start reached Temporal before the describe and Temporal answered the describe ("A late start" names what is left).
- **Pass the names from the loader to the renderer explicitly** (the backlog's other form). Not taken: it changes the engine's start-up path in `serve.ts` and the runner, where the registered symbol changes one line in the module that already holds the names.
- **Leave the Gemini image price until the live run's ledger** (the backlog row's "verify how they are billed before changing the image price"). Not taken: Google's pricing page and image guide now say how they are billed, and the first live run's profile takes its images from this model, so charging nothing for them would make its budgets count low.
- **Turn OpenAI's implicit caching off** (Claude's alternative, from the re-check of 2026-10-21, recorded here at the owner's answer of 2026-10-21 16:14, "Fix the wording and small gaps, file the rest (Recommended)"; keeping caching on is Claude's choice, not put to the owner). A request whose `prompt_cache_options` has mode `explicit` and no breakpoint "does not use prompt caching" (the installed SDK, openai 7.28.0; the re-check read the same in OpenAI's prompt-caching guide). No prompt token would then be written at 1.25× input, and the estimates and the pre-call reservation, which plan every OpenAI input token at the plain rate, would hold. It would also give up the cache reads at 0.1× input (0.05× on `gpt-6.1-sol`) wherever a prompt's opening repeats within the cache's 30 minutes. Kept on for now, by Claude's judgement: no live run has written to the ledger, so it is not known which way it nets, and by Claude's arithmetic caching costs less than none once each written token is read back, on average, more than about 0.26 to 0.28 times (a read saves 0.9× input, 0.95× on `gpt-6.1-sol`; a write adds 0.25×). The first live run with an OpenAI key settles it from the ledger's split of OpenAI input into read, written and plain tokens (backlog "OpenAI cache writes: check them against OpenAI's usage records").

## Consequences

**Positive**

- Every price and model id was read on 2026-10-18, before the first live run, not eleven days earlier; OpenAI's and Google's prices again on 2026-10-21.
- Balanced's images are charged for their thinking and for every answer token Google does not list as the image's, at the text rate. Its budgets therefore do not count low there unless Google bills those tokens at its image rate (backlog "Gemini image thinking tokens").
- An OpenAI call's cache writes are charged at OpenAI's write rate (1.25× input), so the ledger, the spend book and the run budgets no longer count them a fifth low. Balanced and Best use `gpt-6-astra` as the other-family critic, and the OpenAI profile's tiers are `gpt-6-astra` and `gpt-6.1-sol`.
- A run whose start timed out after Temporal accepted it goes on. A run whose error says "Nothing was spent" did not start, except after a late start or a connection reset after Temporal accepted the start (both under Negative).
- Chromium gets no name from `.env.agents` on any start.
- Every configuration's estimate loses one mid-tier call for each VOICE that writes the work: C1, C2, C3, C6, C6a and C7 one; C5 two; C4 one, and a second at the high end when its optional claim log runs. High-end model calls, on every profile: C1 61 to 60, C2 24 to 23, C3 24 to 23, C4 12 to 10, C5 83 to 81, C6 32 to 31, C6a 44 to 43, C7 18 to 17. Some default run budgets drop by 50 cents where no Gemini image offsets the saving. On Best: C6 $6 to $5.50, C6a $7 to $6.50 and C7 $3.50 to $3 with any keys; C1 $15 to $14.50 without an OpenAI key; and C5 $11.50 to $11 without a fal.ai key ($8 to $7.50 without an OpenAI key either). On the OpenAI profile without an Anthropic key: C3 $3 to $2.50 and C6 $6 to $5.50.
- A composed web-page, prose or options recipe can no longer stop at a RELAY step after its earlier steps were paid for.

**Negative, and residuals named**

- **Estimates rise where images come from Gemini** (Balanced and the Google profile), by about $0.015 for each image planned. The estimate plans one Gemini image at about $0.049 (the image's $0.0336, a 300-token prompt and 2,000 text and thinking tokens), against $0.034 before. With item 5's VOICE change, no Balanced default run budget changes, with any set of keys. C3's stays $2.50 with OpenAI and Gemini keys (its high estimate goes from $1.64 to $1.62), $2 with an OpenAI key and no Gemini key, and $1.50 without an OpenAI key. On the Google profile, C1's default budget goes from $3.50 to $4 (its high estimate from $2.75 to $2.88). C2's twelve mood boards, which a run makes one per option while the estimate plans 1 to 3 (backlog "C2 mood boards"), cost about $0.59 on Balanced rather than $0.41.
- **2,000 thinking tokens an image is a planning number.** The real count may be higher or lower; the first live run's ledger shows it (backlog "Gemini image thinking tokens"). If `thoughtsTokenCount` also counts the thought images Google does not charge for, byway's cost leans high.
- **Answer tokens Google does not list.** A Gemini image answer's tokens that `candidatesTokensDetails` leaves out are charged at the text rate ($7.50 per 1M). Neither Google's pricing page nor its reference says how Google bills them. If it bills them at the image rate ($30 per 1M), byway counts low by about $0.014 an image at the largest gap a third party measured (630 tokens). The first live run checks it (backlog "Gemini image thinking tokens").
- **OpenAI estimates plan input at the plain rate.** By default, OpenAI writes any prompt of 1,024 tokens or more that it has not cached, at 1.25× input, and the ledger now charges it so. The advisor's estimate and the gateway's pre-call reservation still plan every OpenAI input token at the input rate, so an OpenAI estimate can be low by up to a quarter of its input cost. Planned as all written, these default budgets would rise:
  - Balanced with an OpenAI key: C6 $4 to $4.50, C6a $4.50 to $5 and C7 $2 to $2.50, and C3 $2 to $2.50 without a Gemini key (with one it stays $2.50, high $1.62 to $1.80).
  - Best with an OpenAI key: C6 $5.50 to $6, C6a $6.50 to $7 and C7 $3 to $3.50.
  - The OpenAI profile: C1 $14 to $15 and C5 $10 to $11; without an Anthropic key also C3 $2.50 to $3, C6 $5.50 to $6.50, C6a $6.50 to $7 and C7 $2.50 to $3 (with one, C6a $5 to $5.50).

  A run budget still stops spending at its limit. How much of a prompt is written rather than read is what the first live run's ledger shows (backlog "Check the advisor's planning numbers against the ledger").
- **A late start.** When Temporal says it has no workflow, the run is marked failed. A start that lands after that describe finds the run failed: the failed start itself, which Temporal was still handling, or another delivery's start of the same run that reaches Temporal just after the describe. The second needs the start that wrote the run to fail while the engine still answers (with a timeout, say, which the Temporal client does not retry); a byway restart cannot cause it, since byway stops its web process before its engine and OPS-2's watch stops byway when the engine stops under it. A second delivery is itself rare: the screen sends a run's id again only after a Start got no answer. The late start's calls are refused; between the describe and that store write, which follows it at once, a call could begin (backlog "Paid-call residuals named only in ADRs").
- **A workflow left under a failed run.** After a late start, or when Temporal had accepted a start but byway could not ask it ("byway could not ask" in item 3, or a connection reset after Temporal accepted the start), a workflow runs under a run the store shows as failed. Its calls are refused and nothing of it is shown. It does not always end at once: a recipe whose first step is a question (C4, C6 and C7 open with an optional step's question) opens that question and then waits, since an answer to an ended run is refused, Cancel does nothing to an ended run, and the engine's start-up reconcile leaves ended runs alone, so a restart of byway does not end it. It waits until byway's workflow code changes: the next engine start after such an update terminates every running run workflow that another workflow bundle started (`retireStaleRuns`, in `versioning.ts`, which runs before the reconcile), this one included, and withdraws its question. Until then it costs nothing and is not seen, and the workflow stays open in the engine (backlog "Paid-call residuals named only in ADRs").
- **With the engine down, a Start now waits about twice as long for its answer.** The describe goes through the Temporal client's own retries, as the start does: in @temporalio/client 1.24, ten attempts of a call that fails with UNAVAILABLE, with waits from about 0.17 s growing 1.7 times to at most 5 s, each ±20%, about 20 s in all (15.8 to 23.7 s). Against a closed port on 2026-10-21 a start failed after 20.1 s and its describe after 20.3 s, so a Start's 503 comes after about 40 s rather than about 20 s. byway sets no deadline of its own on either call. When the engine's port closes, OPS-2's watch stops byway within about 10 to 24 s, before such a describe can end; the longer wait reaches the person when the engine's port still accepts connections while its calls fail (backlog "Run start: the describe doubles the wait when the engine is down").
- **Code 14 and reset connections keep "Nothing was spent"** when byway cannot ask Temporal afterwards: an engine that is not there runs nothing. A connection reset after Temporal accepted the start is the exception; the backlog asked only about code 4, and this was judged too rare to word for (Claude's judgement; backlog "Paid-call residuals named only in ADRs").
- **Four providers' billing of failed requests, and OpenAI's of a moderation block, are still assumptions.** If any is billed, budgets count low.
- **Rates byway does not record** (Decision 1). Google's context-cache hits are charged at the input rate, so Google calls that hit the cache are recorded above their cost, as `gpt-6-luna`'s would be (no profile uses it). The others apply to requests byway does not make; were one made, most would be recorded below their cost.
