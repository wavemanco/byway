# arch

## Summary
Recommendation: Approach A. It is a TypeScript-first, local-first monorepo built from: a Next.js studio, Temporal for durable orchestration, a Postgres experiment database, a runner that gives each candidate its own hardened Docker sandbox with a pinned Playwright renderer, and a model gateway we build ourselves. That gateway is the only path out for every model, image and video call. A also takes two pieces from the other approaches. From B: a Python evaluation and analysis worker on its own Temporal task queue. It uses Inspect AI for held-out AI judges and automated metrics, plus DuckDB to Parquet to R/Python for the statistics. From C: a sandbox adapter that can switch to Vercel Sandbox for big confirmatory batches, and a separately hosted rater app.

Why A:
- The configurations are long-running, branching workflows with human checkpoints that run for hours. That is Temporal's core strength, and a TypeScript workflow can call Python activities.
- The UI must be product-grade, which means React/TypeScript.
- Whether the results are publishable depends less on the framework than on four rules the backend enforces:
  1. Every model call goes through one gateway that logs it, caps spend and pins the provider.
  2. Every artifact is stored by its content hash, and every run carries a manifest.
  3. Production and evaluation are kept apart, so the loop's critic can never be the success judge, and raters see only blinded stimulus bundles.
  4. The design matrix is frozen before launch, and runs are scheduled in interleaved, randomized order.

Reproducibility has to come from archiving, not re-running. Claude Opus 4.7 and later return a 400 error for any non-default temperature, and API inference is nondeterministic because server batch sizes vary with load. So the plan is replicates plus a full archive of every request and response.

Facts about this machine (checked):
- Docker Engine 29.5.3 runs on WSL2 with 16 CPUs and about 15 GB of RAM for its VM; the host has 31 GB.
- Node 24, Python 3.13, uv and pnpm are installed. R, psql and gVisor are not.
- That is enough for about 5–7 concurrent candidate sandboxes: fine for building and pilots, too slow for the confirmatory study, so that study should burst to cloud sandboxes.
- The project sits in OneDrive. The repo, the database and the artifacts should move to the WSL ext4 filesystem.

User-owned choices are listed as questions: hosting account, where rater data lives, ethics approval, who performs the human steps, and the network policy for sandboxes.

## Recommendations
### Overall architecture [high]
Adopt Approach A: a pnpm + uv monorepo with these parts. (1) apps/studio: Next.js, run locally. (2) apps/rate: Next.js, deployed publicly on its own. (3) services/orchestrator: Temporal TypeScript workflows. (4) services/sandbox-runner: one hardened Docker container per candidate, behind a SandboxProvider interface with Docker and Vercel Sandbox adapters. (5) services/model-gateway: the only path out for every LLM, image and video call. (6) Postgres as the experiment database. (7) A content-addressed artifact store. (8) py/eval: a Python Temporal worker running Inspect AI judges and automated metrics, plus the analysis code.
- Why: Only A covers all four needs together: a product-grade UI, durable human-in-the-loop runs lasting hours, local-first development, and publishable evaluation. B's strength (Inspect's logging and judges) and C's strengths (microVM burst capacity and a hosted rater app) attach to A as components. Neither can host the whole system cleanly: Inspect is a batch eval runner, and Vercel's sandboxes and Vercel World run only in the cloud.
- Src: https://temporal.io/blog/community-threads-is-it-possible-to-write-a-single-workflow-with-different; https://inspect.aisi.org.uk/agent-bridge.html; https://vercel.com/docs/vercel-sandbox/pricing; https://workflow-sdk.dev/worlds/postgres

### Durable orchestration and how configurations are represented [medium]
Use Temporal. Locally, run `temporal server start-dev --db-filename` so state survives restarts. Later, use Temporal Cloud's Developer plan rather than self-hosting. Write ONE interpreter workflow that executes a versioned, hashed, declarative config spec (JSON) compiled from the grammar. Do not hand-code a workflow per configuration. Map the grammar like this:
- xN, each[...] and replicates: child workflows (one per candidate).
- loop-until: a bounded loop that keeps the hidden threshold in workflow state, never in any prompt.
- ?H and pick(H): Temporal Updates sent from the studio's human-task inbox, or an automated pick policy chosen per study.
- BANK: an activity that writes to the database.
Pass artifacts only as content hashes, never as payloads.
- Why: Temporal's dev server is a single binary with SQLite persistence and a web UI on port 8233. Updates durably record a human's approval in the event history, which doubles as an audit trail for the paper. Polyglot task queues let TypeScript workflows call Python judge and analysis activities. The limits are real: 2 MB per payload and 51,200 events or 50 MB per history. Child workflows per candidate plus passing hashes keep a 4-candidate × 5-iteration C1 run well under them. One interpreter over a spec is what lets the UI hide the grammar while experiments stay exact: the spec hash is the condition's identity in the data. Cloud cost is $50 per million actions, so a study of about 1,000 runs costs tens of dollars, not hundreds.
- Src: https://docs.temporal.io/cli/server; https://docs.temporal.io/encyclopedia/workflow-message-passing; https://docs.temporal.io/cloud/limits; https://docs.temporal.io/cloud/pricing; https://temporal.io/blog/community-threads-is-it-possible-to-write-a-single-workflow-with-different

### Sandboxing untrusted generated code and rendering [high]
Give each candidate one sandbox: the agent CLI (Claude Agent SDK, or Codex CLI for the ASSET route), the workspace and its dev server. Harden it with Anthropic's flags: `--cap-drop ALL --security-opt no-new-privileges --read-only` plus tmpfs, a seccomp profile, `--pids-limit`, memory and CPU caps, a non-root user, and `--network none`. The only way out is a Unix socket to the gateway and to a pinned npm registry mirror. No API keys ever enter a sandbox. Rendering happens in a separate container: the pinned Playwright image (v1.63.0, recorded by digest) running as the non-root pwuser with Playwright's seccomp profile. It loads a frozen static export with external requests blocked except an allowlist (e.g. fonts), and uses fixed viewports, locale, timezone and fonts. Add gVisor later only if the threat model demands it.
- Why: Playwright's own docs say its image is not meant for untrusted sites, and that running as root disables Chromium's sandbox, so a non-root user plus seccomp is required. Anthropic's secure-deployment guide gives exactly this container recipe and recommends a proxy that injects credentials. gVisor costs up to 10–200× on file-I/O-heavy work, and npm installs and builds are exactly that, so it is a poor default for dev servers. Rendering in its own pinned container separates the generator from the critic's view and makes screenshots comparable across conditions.
- Src: https://playwright.dev/docs/docker; https://code.claude.com/docs/en/agent-sdk/secure-deployment; https://code.claude.com/docs/en/agent-sdk/hosting

### Burst capacity for confirmatory runs [medium]
Use the local Docker provider for development and pilots, and the Vercel Sandbox adapter (Pro plan) for confirmatory batches. Run an entire confirmatory study on ONE backend, or balance backends across conditions and record the backend as a covariate. Size it with the per-candidate-hour estimate: a 4 vCPU / 8 GB sandbox at about 10% CPU costs about $0.17 for memory plus $0.05 for CPU, so about $0.22 per candidate-hour.
- Why: Local capacity: Anthropic suggests 1 GiB, 1 CPU and 5 GiB of disk per agent as a starting floor. Add a dev server and Chromium and each candidate needs about 2–3 GB, so a ~15 GB Docker VM fits about 5–7 candidates, i.e. 1–2 four-candidate C1 runs at once. An illustrative study of 720 runs at about 1.5 h each would take weeks locally but about a day at 40-way parallelism. Vercel Sandbox gives Firecracker microVMs, 24 h sessions and 10,000 concurrent sandboxes on Pro. Hobby is capped at 45 minutes and 10 concurrent. Sandbox cost stays an order of magnitude below token cost. Switching backends mid-study would confound conditions with environment (timeouts, network), so the backend must be held constant or balanced.
- Src: https://vercel.com/docs/vercel-sandbox/pricing; https://code.claude.com/docs/en/agent-sdk/hosting

### Model access layer (Anthropic, OpenAI, Gemini, OpenRouter, fal) [high]
Build a thin TypeScript model gateway that is the only egress for model traffic. Agent CLIs reach it via ANTHROPIC_BASE_URL and OPENAI_BASE_URL, and image and video jobs go through it too. It does six things:
- injects the API keys;
- writes every request and response, with its hash, to the artifact store and the model_calls table (model ID served, provider, tokens, cost, latency);
- enforces per-study budget caps, with a cost estimate shown before launch and a hard stop when the cap is hit;
- paces traffic against provider rate limits;
- pins OpenRouter with `provider.only=[x]` and `allow_fallbacks=false`;
- downloads fal media into the artifact store immediately.
Use first-party APIs for every primary arm. Use OpenRouter only for models with no first-party access, and use Vercel AI Gateway only if the C path is chosen later.
- Why: By default OpenRouter load-balances, so identical requests can be served by different providers. That is a hidden confound unless pinned and logged. fal result URLs are public and expire, so outputs must be copied into our store. A single egress point also enforces the protocol's rule that critics see only rendered views, and keeps keys away from generated code. Anthropic's docs recommend exactly this base-URL proxy pattern. The March 2026 LiteLLM PyPI compromise stole environment keys from proxy hosts, which argues for a small proxy we control, with hash-pinned dependencies, over a large third-party one.
- Src: https://openrouter.ai/docs/features/provider-routing; https://fal.ai/docs/model-apis/model-endpoints/queue; https://code.claude.com/docs/en/agent-sdk/secure-deployment; https://www.netspi.com/blog/executive-blog/ai-ml-pentesting/litellm-supply-chain-compromise/; https://vercel.com/docs/ai-gateway/usage-and-pricing

### Reproducibility design (what the paper's methods and replication package rely on) [high]
Every run gets an immutable manifest recording:
- the config spec hash and prompt-template hashes;
- the exact model IDs (plus the model ID returned in each response) and the provider route;
- the Agent SDK and CLI versions;
- the container image digests and the Playwright/Chromium version;
- the SEED strings drawn from the shell RNG, randomization seeds, the sandbox backend and region, and timestamps.
Keep a replay cache keyed by request hash. Lock the design before launch: the harness refuses conditions outside the frozen, preregistered matrix, and the scheduler interleaves conditions in randomized order. Model choice is governed by retirement dates: use only models whose retirement is at least 6 months after data collection ends. Ship a replication package of Parquet tables, the artifact store, image digests and analysis scripts.
- Why: Re-execution cannot reproduce results. Claude Opus 4.7 and later reject non-default temperature, and API nondeterminism comes from batch size varying with server load. So the science rests on replicates plus a complete archive, which also allows re-judging the same artifacts later with new judges. Retirement dates matter now: Haiku 4.5 is listed as not retiring sooner than Oct 15, 2026, and Sonnet 4.5 retires Nov 30, 2026. The article's Fable 5 and Opus 5 are listed as available until at least June and July 2027. Interleaved scheduling keeps time drift (provider load, silent updates) from lining up with condition.
- Src: https://platform.claude.com/docs/en/about-claude/model-deprecations; https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/; https://code.claude.com/docs/en/agent-sdk/hosting

### Separate the evaluation plane from the production plane [high]
A run ends by freezing a stimulus bundle. Each bundle has an opaque ID; metadata, HTML comments and EXIF are stripped; and it holds screenshots at fixed viewports, a scroll-capture video and a static HTML snapshot. Everything that judges reads ONLY bundles:
- Held-out AI judges and automated metrics run as Inspect AI tasks in the Python worker.
- Human ratings come from the rater app.
Judge models must come from a different family from the loop critic, and their prompts and references must not be used in the loop. Inspect logs, which record model_snapshot and token use, are stored next to the ratings under the same stimulus IDs.
- Why: 03-configurations requires success to be 'judged outside the loop' and says the loop's own critic is never the success judge. Enforcing that in the data model makes blinding auditable. Inspect is an established, citable eval framework with OpenRouter pinning, logs, caching and pandas dataframes, so reviewers get a recognizable evaluation stack without it having to run the generation side.
- Src: https://inspect.aisi.org.uk/dataframe.html; https://inspect.aisi.org.uk/providers.html; file:///C:/Users/arvik/OneDrive/Documents/ActAI/protocol/03-configurations.md

### Critic isolation implementation [medium]
Make the critic call the orchestrator's job, not a subagent spawned by the worker. After each worker turn, the workflow calls render, then calls the critic with only the screenshots and references under the frozen critic prompt. It returns the critique text to the worker; the score and threshold stay in workflow state. Report this as an implementation detail in the methods. If fidelity matters, add a small arm that uses the article's in-agent subagent.
- Why: This enforces the protocol's port rules in code (the critic sees only views, and the threshold stays hidden), makes every critic call a logged and costed record, and works the same way for Claude Code and Codex workers. In the article, Claude Code spawned the critic itself. That is equivalent in intent but cannot be audited.
- Src: file:///C:/Users/arvik/OneDrive/Documents/ActAI/protocol/03-configurations.md; https://inspect.aisi.org.uk/agent-bridge.html

### Public rater endpoint [high]
Deploy apps/rate on its own to a hosted platform, with its own small database (or a schema) and an assignment API. Integration with Prolific: an external_study_url that passes {{%PROLIFIC_PID%}}, {{%STUDY_ID%}} and {{%SESSION_ID%}}, and a completion-code redirect. Serve stimuli from a separate, cookieless origin (CDN or bucket). Default to screenshots and videos. Show live HTML only inside `<iframe sandbox="allow-scripts">` WITHOUT allow-same-origin, and never link to running sandboxes. Ratings are append-only events that sync back into the local experiment database.
- Why: The laptop cannot be the public endpoint, so the rater plane is the one part that must be hosted from day one. MDN warns that allow-scripts combined with allow-same-origin lets embedded content remove its own sandbox. Generated pages are untrusted code, so they must never share an origin with the app. Prolific's study object supports exactly this URL-placeholder and completion-code flow.
- Src: https://docs.prolific.com/api-reference/studies/the-study-object; https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe

### Storage and database [high]
Postgres (in Docker) is the experiment database. Its tables: studies, prereg_locks, conditions (with spec_hash), tasks/briefs, runs, steps, seeds, model_calls, cost_ledger, artifacts (sha256), stimuli, judges, raters, assignments, ratings, exclusions. Event tables are append-only. Store artifacts on local disk under the WSL filesystem, behind an S3-shaped interface, and move them later to Cloudflare R2 or S3. Do not adopt MinIO.
- Why: MinIO's community edition went into maintenance mode in December 2025, and no fork has gained traction. Local S3 alternatives (SeaweedFS, or Garage under AGPL) add an operational burden that is not needed yet. A filesystem store addressed by content hash is simplest and deduplicates repeated renders. Docker's WSL guidance says bind mounts are much faster from the Linux filesystem than from /mnt/c, and OneDrive sync can corrupt live database and artifact files.
- Src: https://infoq.com/news/2025/12/minio-s3-api-alternatives/; https://docs.docker.com/desktop/features/wsl/best-practices/

### Analysis pipeline [medium]
Python and R share one data contract: DuckDB ATTACHes Postgres read-only and COPYs frozen snapshots to Parquet, so every analysis is tied to a dated, hashed data freeze. Use Python (uv-locked; pandas/statsmodels plus Inspect's evals_df and samples_df) for judge logs and cost analysis. Use R for mixed-effects, ordinal and pairwise (Bradley–Terry) models (renv-locked). Render reports with Quarto. Install R; it is not on the machine.
- Why: Using Parquet snapshots means there is no ETL service to run, the files load in both languages, and the snapshot is what goes into the replication package. Inspect's dataframes already flatten judge logs, with model snapshot and tokens.
- Src: https://duckdb.org/docs/current/core_extensions/postgres/overview.html; https://inspect.aisi.org.uk/dataframe.html

### UX approach (hiding the block grammar) [medium]
The studio offers 'recipes' (Make distinctive landing pages = C1; Write a story = C6a; ...). Each recipe shows a short wizard (brief → references → budget → what you'll be asked to decide), then a run timeline of plain-language step cards ('Exploring 4 directions', 'Critic round 3 of 5'). Alongside it: a candidate gallery, a single human-task inbox for every ?H checkpoint, and a live cost meter compared with the pre-launch estimate. The wiring view (the block graph) is an advanced toggle that only reads the spec. The experiment designer is a separate mode: arms × tasks × replicates → power-based budget → lock → launch.
- Why: The esoteric part is the notation, not the concepts. Because the config spec is the single source of truth, simple UI and exact experiments can coexist. A single inbox is also what is needed to send ?H tasks to blinded human designers in experiments.

### Build order [medium]
Phase 0 (harness spine): gateway, Docker sandbox runner, render container, Temporal interpreter running C1 plus the plain and 'be creative' baselines, artifact store, database, and the cost estimator. Phase 1: stimulus bundles, the Inspect judge worker, the rater app and a Prolific pilot (n≈20). Phase 2: studio polish and the experiment designer. Phase 3: Vercel Sandbox adapter, hosted deployment and Temporal Cloud. Build the rater UX to a high standard early, because rater experience affects data quality. Studio polish can trail.

## Risks
- The project folder is inside OneDrive. Live Postgres files, Temporal SQLite and gigabytes of artifacts in a synced folder risk sync conflicts and corruption, and bind mounts from /mnt/c are slow. => Move the repo and all data directories to the WSL ext4 filesystem (e.g. ~/actai). Keep only the protocol docs in OneDrive. Back up with explicit dated snapshots, such as pg_dump and an rsync of the artifact store.
- Model nondeterminism, plus temperature that cannot be set on Claude Opus 4.7 and later, makes exact re-execution impossible. => Treat runs as samples: replicates per cell, an archive of every request and response, and a replay cache. State in the paper that reproducibility is archival. Analyze with models that include run-level random effects.
- A model is retired or silently changes mid-study (Haiku 4.5 is listed as not retiring sooner than Oct 15, 2026; Sonnet 4.5 retires Nov 30, 2026). => Choose models whose retirement is at least 6 months after data collection ends. Record the model ID returned in every response. Interleave conditions over time so any drift does not line up with condition.
- OpenRouter's default routing serves the same model from different providers, adding an unrecorded confound. => Use first-party APIs for primary arms. For any OpenRouter call, set provider.only and allow_fallbacks=false, and log the provider that served it.
- Generated code or prompt injection escapes, or steals API keys. => Keep keys out of sandboxes; the gateway injects them. Use network none plus a proxy socket, cap-drop ALL, a non-root user, seccomp, read-only root, and pids and memory limits. Run Playwright as non-root with seccomp. Use a pinned registry mirror instead of open npm.
- Raters' browsers run untrusted generated JavaScript (XSS or phishing), or stimuli leak condition labels. => Show screenshots and videos by default. Serve live HTML from a separate cookieless origin in sandbox="allow-scripts" iframes without allow-same-origin. Give bundles opaque IDs and strip metadata, titles, comments and EXIF. Run an automated leak scan before a study is published.
- Supply-chain compromise of dependencies that see keys (e.g. the LiteLLM PyPI incident of Mar 24, 2026). => Use lockfiles with hashes (pnpm, uv), images pinned by digest, Renovate with delayed adoption, a minimal gateway dependency set, and keys only in the gateway process.
- Temporal history and payload limits break long C1 runs with many iterations. => Use one child workflow per candidate, pass only hashes, cap each loop as the protocol already specifies (probe 2, max 5), and use continue-as-new for series configurations such as C3.
- Local capacity (about 15 GB Docker VM) and provider rate limits make confirmatory runs take weeks, and mixing local and cloud backends confounds the results. => Use local runs for pilots only. Run the confirmatory study on one backend (Vercel Sandbox, Pro). The gateway paces requests to rate limits. Request higher API tiers before launch. Record the backend as a covariate if it cannot be held constant.
- Cost overrun from the multiplicative fan-out (candidates × iterations × images). => Show an itemized estimate before launch, computed from the spec and current prices. Enforce hard per-study and per-run budget stops in the gateway. Show a live cost meter against the estimate. Run a pilot to calibrate per-run cost before the power-sized study.
- Human checkpoints (?H, pick, distill) bring experimenter bias or uncontrolled variance into the experiments. => In experiments, ?H is either an automated, preregistered pick policy or a task sent to blinded human designers through the inbox, who see no condition labels. Log human time per task.
- Building the Apple-grade studio first delays the harness that Paper 1 depends on. => Follow the phases: harness spine and rater app first, studio polish after the pilot. The config spec decouples the UI from the engine.
- fal media URLs are public and expire, and generated media can leak or disappear. => The gateway downloads results into the artifact store immediately. Set short media expiration on the provider side. Never share provider URLs.
