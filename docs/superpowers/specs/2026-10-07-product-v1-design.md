# byway product v1

**Status:** design for implementation, 2026-10-07. The user asked to "go with the product track. complete it first. use subagents with dedicated worktrees if needed." Decisions the user did not make explicitly are recorded as Delegated ADRs ([ADR-0064](../../adr/0064-product-v1-local-first-web-app.md) to [ADR-0068](../../adr/0068-contracts-first-parallel-build.md)).

## 1. What v1 is

A **local-first web app** on the shared engine ([ADR-0041](../../adr/0041-shared-engine-pinned-research-versions.md)) that delivers the north star ([ADR-0042](../../adr/0042-product-north-star-recommend-or-compose.md)):

1. You describe a problem in your own words.
2. byway recommends one of the eight configurations (C1–C7, C6a) through the protocol's chooser, or composes one from the blocks when none fits ([ADR-0058](../../adr/0058-design-time-composition-only.md)), with an honest evidence label (all "Untested" until studies report, CR11).
3. You run it end to end. The AI does the AI steps; you do the human steps (pick, react, trim, compare, write) inside the app.
4. You get the deliverable (a page, a memo, a story, options, a storyboard, a diff) and can export it.

**Done means:** all eight configurations run end to end in demo mode (mock models, no keys) and, with keys in `.env.agents`, against real models; every human checkpoint has a working UI; the recommender and composer work; labels are computed; product data stays out of research; the whole thing starts with one command and is covered by unit, integration and end-to-end tests.

**Not in v1:** hosted multi-user deployment and auth, billing, the MCP/skill channels, mobile layouts beyond responsive basics, the research harness's Judge app and study machinery, and video generation when no fal.ai key is configured (the C5 step then stops at the storyboard and images, and says so).

## 2. Architecture

```
apps/web            Next.js 16 product app (UI + route handlers). Temporal client. Binds 127.0.0.1.
packages/contracts  Shared interfaces (gateway, store, runner, advisor, presentation).   [done in Phase 0]
packages/protocol   Ports, blocks, rules, exceptions, media.                              [exists]
packages/recipe     Recipe IR, hashing, derivations.                                      [exists]
packages/validator  Rule checks.                                                          [exists]
packages/catalog    Recipes C1–C7, C6a (+ Study 1 arms), presentation data, chooser data. [WP-A extends]
packages/gateway    Model gateway: providers, profiles, prices, ledger, caps, mock.       [WP-C]
packages/store      SQLite (node:sqlite) records + content-addressed artifact files.      [WP-S]
packages/prompts    Versioned prompt templates for every prompt id, and a renderer.       [WP-P]
packages/runner     Temporal workflow interpreter, activities, worker, dev engine.         [WP-D]
packages/advisor    Recommender (chooser + intake), composer, labels, estimates.          [WP-E]
```

Dependency direction: `web → {advisor, runner (its `./client` entry only), store, gateway, prompts, catalog, contracts}`; `runner → {gateway, store, prompts, catalog, recipe, validator, contracts}`; `advisor → {gateway, prompts, catalog, recipe, validator, contracts}`; nothing in `packages/` imports `apps/`. A guard test (`apps/web/test/guard-boundaries.test.ts`) enforces these sets. The research evaluation side (future `py/eval`, judge instruments) is never imported by product code (CR12).

**Process model (local).** `pnpm dev` starts: a local Temporal dev server (via `@temporalio/testing` `TestWorkflowEnvironment.createLocal` with a persistent `dbFilename`, port 7233), the runner worker, and `next dev` on `127.0.0.1:3000`. `pnpm demo` does the same with the mock provider forced on.

**Temporal on this machine.** SWC (Temporal's default workflow transpiler) refuses its cache folders here because their permissions include a sandbox group. Workflow code is therefore compiled to JavaScript with esbuild first (`packages/runner/scripts/build-workflows.ts`), and the worker bundles the `.js` (verified in a spike: a workflow with an activity and a human Update completed). The esbuild step must bundle all workspace imports into that one file (only `@temporalio/*` stays external), because the workspace packages export TypeScript sources that Temporal's bundler would otherwise hand to SWC.

**Data.** `BYWAY_DATA_DIR` (default `%LOCALAPPDATA%\byway` on Windows, `~/.byway` elsewhere; never inside OneDrive or the repo). It holds `byway.sqlite` (with its `-wal` and `-shm` files while open; it holds the spend book too, [ADR-0095](../../adr/0095-paid-calls-have-a-durable-spend-book.md)), `artifacts/sha256/…`, `ledger.jsonl` and `ledger.jsonl.head` (and, only after a crash cut an append short, the torn line set aside as `ledger.jsonl.damaged-<time>-<pid>`), `exposure.jsonl`, `temporal.sqlite` and `bin/` (the engine's copy of the Temporal CLI). The backup unit is the whole directory, copied with byway and its engine stopped, and a restore replaces the whole directory ([ADR-0094](../../adr/0094-backup-unit-is-the-data-directory.md); README "Back up and restore"). At start, byway reports what a partial restore left behind (a check of the database file, the artifact files and the ledger, of calls the spend book holds that the ledger lacks, of runs whose recorded cost the spend book lacks, and of ledger lines waiting to be acknowledged; it changes no run record or file, and the spend book reads in ledger lines it has not seen, as the first model call would), and the engine terminates run workflows the store does not have before its worker polls ([ADR-0096](../../adr/0096-partial-restores-reported-at-start.md)).

**Keys.** Read from the process environment, loaded at startup from `.env.agents` at the repo root if present (gitignored, ADR-0009). Variables: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `FAL_KEY`. Keys never enter the database, the ledger, artifacts, logs, prompts or the browser. This is enforced where text crosses a boundary ([ADR-0088](../../adr/0088-provider-boundary-held-keys-and-media-admission.md)). A request body holding a configured key (its exact value, or a `:`-part of 16+ characters) is refused before it is stored. The gateway refuses any model, image or video request whose text holds one, and never hands on an answer that holds one (the paid call is still ledgered). Its diagnostic copies are redacted: stored request and response bodies, the served model and upstream host, and error messages. Data stored before that change is not scanned, and images are sent unchecked. The page renderer's Chromium, which the engine starts, gets none of them in its environment, nor anything secret-looking or any other name from `.env.agents` ([ADR-0084](../../adr/0084-renderer-launch-without-secrets.md)).

## 3. Runs: how a recipe executes

The runner interprets the recipe tree (`byway.recipe/1`) as a Temporal workflow. Workflow state holds port values by reference (artifact ids, short texts); activities do all I/O.

### 3.1 Port values

| Port | Value |
|---|---|
| `intent` | The problem text plus brief fields |
| `brief` | Text |
| `artifact` | An artifact id; its format comes from the recipe's `medium` (`MEDIUM_FORMAT`) |
| `view` | For `web-page`: labelled PNG renders of three surfaces — wide screen (full page at 1440, tiled to ≤ 2576 px per tile), phone (390 wide, tiled) and first screen (1440×900) — narrowed by a render step's `renders` knob ([ADR-0079](../../adr/0079-phase-4-runner-records.md)). For `media`: the storyboard text and each shot's frame. For `text` media: the artifact's clean text |
| `critique` | Text |
| `score` | Number parsed from the critic's "Score: N/10" line (or rank) |
| `taste`, `voice` | Human text |
| `tells` | The tell catalog text for the medium (from `@byway/prompts`) |
| `refs` | Artifact ids supplied by the user |
| `seed` | Generated in an activity with `crypto.randomBytes`; passed to SEED steps only; the runner checks it never appears in the work: artifacts, views and notes of the run (PR3; the gateway's stored request bodies necessarily contain it) |
| `option_set<artifact>` | An ordered list of artifact ids (candidates) |
| `anchor` | The artifact id of a relay link's exact end state (C5: the last frame of a clip), which the next link starts from |
| `asset` | Artifact ids of generated media kept beside the work (C2: rough mood images that never become the deliverable) |

### 3.2 Step execution

| Step | Executor |
|---|---|
| `actor: model` (build, seed, fix, asset, critic, judge, check, cut proxy, tells-sweep, tells-compare proxy, select, vision) | `modelStep` activity: render the step's prompt template with its slots, call the gateway at the step's tier, parse the output by role (HTML/markdown/JSON extraction for builders; critique + score for critics; a label for judges and selectors; a directive for CUT; hits for the TELLS sweep; keep/revert for the TELLS compare) |
| ASSET on `web-page` | `assetStep`: ask the model for up to the slot count of image briefs (JSON), generate them through `gateway.image`, then ask the model to integrate them; images are served from the artifact store |
| `actor: tool`, role `render` | `render` activity: Playwright Chromium, network blocked except an allowlist (Google Fonts, jsDelivr, unpkg, cdnjs, the local artifact route) that every redirect hop must pass too ([ADR-0096](../../adr/0096-partial-restores-reported-at-start.md)), each response read up to 20 MiB and no further ([ADR-0099](../../adr/0099-paid-operations-keyed-to-their-caller.md)), reduced motion, fixed viewport; prose media return the text. The same renderer draws HTML references and lineup cards for every medium. Its Chromium is launched in one place, with one stated policy and no secrets in its environment; a Chromium that cannot start fails the step plainly, without retries, and a web-page run whose renderer cannot start is refused before its first step. Whether Chromium's OS sandbox is on awaits the owner's decision; until then it stays off, as it always was ([ADR-0084](../../adr/0084-renderer-launch-without-secrets.md)) |
| `actor: human` | Open a checkpoint (kind by role, below), wait for the `resolveCheckpoint` Update, map the resolution to the step's produced ports |
| `pick(H,k)` | Checkpoint `pick` with the candidates' renders |
| `pick(C,k)` | The pick's judge step (a model judge or select step) via `modelStep`, returning labels; a judge that names no draft fails the run |
| `optional` | Checkpoint `confirm` with the trigger text as the question |
| `route` | The choice in `StartRunInput.routes`, else checkpoint `choose` |
| `loop` | Run the body; the gate decides right after the critic or check that reports to it (its exit point: the rest of that round, later relay links included, does not run), comparing the critic's score with the hidden threshold (never put in any critic prompt); stop at the threshold, at the plateau rule or at `max`. Every way out at the cap takes one turn ([ADR-0093](../../adr/0093-every-loop-exit-at-the-cap-follows-one-policy.md)): with `onCap: human`, a critic or check loop asks "Use the best version so far?" and a person's loop asks "That was the last planned round. Use this version? No allows up to N more rounds, once."; No raises the cap once; at the raised cap a critic or check loop takes its best snapshot and a person's loop asks a last `choose` (Use this version, or Stop the run, which ends the run cancelled). A loop whose judge had nothing to see (a relay link that made no clip) ends that round as it is, not checked, at whatever round: that is not a way out at the cap, so it asks nothing ([ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)). Best-snapshot re-rank as a fresh judge call |
| `replicate n` / `each` | Run candidates concurrently inside the workflow, within the engine's limits (§4); candidate index recorded on events and checkpoints. Each candidate of `each` runs on its own option, with no option list |
| `audit` | Run the lenses concurrently on the same input; their critiques are joined under the lens names and kept beside the work with their notes, never written into it. No score leaves an audit |
| `gate` (one-shot) | Run the body once and compare its own critic's score with the hidden pass condition (critic-score or critic-rank only); only the body's critique is kept. On a fail re-run `retry.stage` from that stage's entry ports, up to `retry.times` (a retrying gate sits at stage level, never inside replicate, each or an audit), then checkpoint `confirm`; its No ends the run as failed |
| `relay` | One link per storyboard shot (up to `maxLinks`), strictly in sequence; the first link starts from shot 1's frame (the anchor-frames ASSET step), each next one from the previous clip's last frame. Relay model steps answer `relay:media`; the runner then calls `gateway.video` ([ADR-0069](../../adr/0069-product-c5-relay-and-honest-skips.md)) and records the clip and its last frame on the shot. A link with no frame to start from (shot 1's frame was not made) finishes skipped: "Shot N has no frame to start from, so no clip was made." ([ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)) |
| ASSET on `options`, `media`, `prose` | `asset.briefs:<medium>` → `gateway.image` per brief; on `prose` then `asset.integrate:prose`; on `options`/`media` the runner attaches `imageArtifactId` to each option or shot (no integrate call). How many briefs a step may write is what its prompt declares (`images:` front matter: one per shot or option, or a range); one slot identity decides coverage, purchases, attaching and the anchor, and coverage is checked before anything is bought. A short answer gets one feedback retry, then the step makes what it can and its note names what is missing; only a malformed answer fails it. The relay anchor is shot 1's frame, or none ([ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)) |
| Steps with no v1 executor (C5 `matte`, `vo-audio`), and relay links without a usable video model | Finish as skipped with a plain note ("Compositing is not available in byway yet", "No voice-over audio provider is configured", "No video provider key is configured"); the artifact and anchor pass through unchanged (ADR-0069) |

**Critic modes.** A GREAT-mode critic runs in GREAT mode only with at least 3 user-supplied references (up to its `refs` knob, shuffled); with fewer it runs in OK mode against the hidden 9/10 bar and the step says so ([ADR-0071](../../adr/0071-great-critic-falls-back-to-ok-without-references.md)). `critic-rank` gates pass when the rank is at or better than the threshold (lower is better); `critic-score` gates when the score reaches it. Loops with metric `human` open a `confirm` checkpoint after each round but the last ("Is this ready?"; yes ends the loop); the last planned round asks the cap's question instead, so running out of rounds is never taken as a yes (ADR-0093); `check-clean` loops stop when the check answers `No defects.`, or, inside a relay link that made no clip, when there was nothing to check (the check is skipped with its reason).

**Prompt slots by port.** The runner fills the slots of the ports a step consumes and of those it reads when they are there (`reads`, [ADR-0089](../../adr/0089-recipe-ir-optional-reads.md)); a port with no value fills its slot with an empty string, so a template's `{{#if}}` section leaves it out: `intent` → `problem`; `brief` → `brief`; `artifact` → `artifact` (never for critic, judge, check, tells-sweep or tells-compare steps: port rule 1); a text `view` → `view`, a screenshot `view` → attached images; `option_set` → `options` (labelled A, B, C…); `critique` → `critique` (audit lenses joined under their names); `taste`, `voice`, `tells`, `seed`, `refs` → slots of the same name (reference images are attached); `score` never reaches a prompt (port rule 2).

**Views by medium.** `web-page`: Playwright screenshots of the wide screen, the phone and the first screen, each captioned. `prose`: the clean Markdown text. `options`: the options as a numbered plain-text list (labels A, B, C… when several sets are compared). `media`: the storyboard as text plus each shot's frame image when it exists; inside a relay link, that shot's line, the frame its clip started from and the clip's last frame, each captioned, or, when the link made no clip, nothing to check (its judge is skipped and the loop ends not checked; [ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)). `code-diff`: the diff text.

**Human checkpoint kinds by role:** `vision` → `react` (a reaction that consumes and produces the same text port revises it in place: it opens with the port's text and its answer replaces it, as C7's spec answers the interview's questions; [ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)); `cut` → `directive`; `tells-compare` → `compare`; `voice` → `write` (initial text = the copy extracted from the artifact; the edited copy is written back by a model step that changes only text and is checked by a diff); the author's draft in C3, C6 and C6a (a human build or fix) → `write`. A model cliché sweep (`tells-sweep`) opens a `select` of its finds when the next step after it in its own seq that consumes a critique (not one that only reads it) is a model fix, nothing before that fix there can put another critique in place of the finds (`replacesCritique`), and no keep-or-revert there is a machine's; only the finds the person chooses reach the fix (TELLS-1, convention C2; `asksSwaps` in `@byway/recipe/semantics`, which the interpreter, the diff, the explainers and the estimate share).

**The person's words at run time ([ADR-0098](../../adr/0098-recipe-limits-disclosure-and-held-voice.md)).** A VOICE write (a human voice step that produces the artifact) sets `voice` to its answer and adds it to the held voice, every VOICE answer on the path; a step that only declares VOICE sets neither. A machine write declared `keepsVoice` keeps every line of the held voice and the latest words that was in the work before it. Any other machine write after the person's words, outside an audit lens or a gate's body, fails the run before it runs.

Every step emits `step-started`/`step-finished` events with cost; every artifact emits `artifact`; the run ends with `run-finished` and the output artifact id.

### 3.3 Purposes and output contracts

Prompts (WP-P), the runner's parsers (WP-D) and the mock provider (WP-C) must agree exactly. Every gateway call carries a `purpose`:
- recipe steps: `<role>:<medium>`, e.g. `build:web-page`, `critic:prose`, `cut:web-page`, `tells-sweep:prose`;
- helpers: `asset.briefs:web-page`, `asset.integrate:web-page`, `voice.apply:<medium>`, `rerank:<medium>`, `advisor.intake`, `advisor.compose`, `advisor.compose.repair`.

| Purpose (role) | The model must answer with |
|---|---|
| `build`, `seed`, `fix`, `asset.integrate`, `voice.apply` on `web-page` | One fenced `html` block holding a complete HTML document (inline CSS/JS; images by the URLs given) |
| same, on `prose` | The Markdown document (optionally in one fenced `markdown` block) |
| same, on `options` | One fenced `json` block: `{"options":[{"title":string,"pitch":string,"rationale":string}]}` |
| same, on `media` | One fenced `json` block: `{"storyboard":[{"shot":number,"description":string,"imagePrompt":string,"durationSec":number,"caption"?:string}],"voiceover":string,"headline"?:string,"tagline"?:string}` (the on-screen copy — headline, tagline, captions — is what the late VOICE edits; the voice-over is locked after the VO script step) |
| same, on `code-diff` | One fenced `diff` block (unified diff), then a paragraph starting `Why:` |
| `critic` | OK mode: the critique as a bullet list, biggest gaps first, then a last line `Score: N/10`. GREAT mode: one `### X` section per item of the lineup, then a last line `Ranking: C, A, E, B, D` (every label once, best first). The critic is never told which item is ours; the runner finds our rank and hands only our item's section to the fix step ([ADR-0072](../../adr/0072-great-critic-ranks-blind.md)). In a mixed-form lineup every item is one card image; a critic that reads text also gets every item's whole words under its label, and an image-only critic's card shows as many words (characters, for text without spaces) as fit one image and ends with a line saying how many were left out; the verdict carries a sentence saying whose words were cut, for the step's note ([ADR-0087](../../adr/0087-lineup-evidence-full-words-and-disclosed-card-budget.md)) |
| `judge`, `select`, `rerank` | Optional reasoning, then a last line `Choice: <label>` (labels A, B, C…) |
| `check` | A bullet list of defects, or the single line `No defects.` |
| `cut` (model) | A bullet list of removals, each starting with a removal verb (Remove, Delete, Drop, Merge), or the single line `Nothing to remove.` |
| `tells-sweep` | One fenced `json` block: `{"hits":[{"pattern":string,"where":string,"alternative":string}]}` |
| `tells-compare` (model) | Optional reasoning, then a last line `Keep: A` or `Keep: B` |
| `vision` (model) | Plain text |
| `asset.briefs` | One fenced `json` block: `{"images":[{"slot":string,"prompt":string,"alt":string,"size":"1024x1024"\|"1536x1024"\|"1024x1536"}]}` |
| `advisor.intake` | One fenced `json` block: `{"answers":[{"questionId":string,"answer":boolean,"confidence":number,"rationale":string}],"routes":{[routeId]:string}}` |
| `advisor.compose`, `advisor.compose.repair` | One fenced `json` block holding a `byway.recipe/1` object |
| `dedupe:<medium>` | One fenced `json` block: `{"keep":[label…],"merged":[{"into":label,"from":[label…]}]}` (labels A, B, C… of the options shown) |
| `overlap:<medium>` | One fenced `json` block: `{"flags":[{"label":label,"overlapsWith":string,"note":string}]}` (annotation only) |
| `relay:media` | One fenced `json` block: `{"clipPrompt":string,"durationSec":number}` — the runner generates the clip from the previous anchor when a video provider is configured; otherwise the step finishes skipped with the note "No video provider key is configured" |
| `asset.briefs:<medium>` | As for web-page: `{"images":[{"slot","prompt","alt","size"}]}`; on `media` one image per storyboard shot (slot = shot number), on `options` one mood image per option (slot = option label), on `prose` illustrations only where the text asks for them. The count is the prompt's (`images:`: `each` on media and options; `1-3` on web pages and C1's `article.ASSET`; `0-3` on the generic prose helper; `0-1` on C3's prompt, whose empty answer the runner honours); a prompt whose minimum is 0 may answer with an empty list, and the step then makes no image and says so ([ADR-0090](../../adr/0090-execution-contracts-for-revising-humans-and-media-steps.md)) |
| `asset.integrate:prose` | The Markdown document with image links (`/api/artifacts/<id>`) placed where they belong; on `options` and `media` there is no integrate call — the runner attaches `imageArtifactId` to each option or storyboard shot |

Parsers take the last fenced block of the expected language, fall back to the whole text, and fail the step with a clear message when the contract is not met (one automatic retry with the parse error appended).

**SEED in the product.** The article has the model generate its random string with a shell command; the product has no shell, so the runner generates the string (`crypto.randomBytes`) and the SEED prompt hands it over with the article's instructions (interpret it for direction, never reveal it). This is a declared product deviation; the PR3 check verifies the string never appears in the work. The nearest published evidence on this form is indirect: in String Seed of Thought v3, App. D.6, a pseudo-random string injected into the prompt ("Seed Injection") generally scored below a string the model writes itself on open-ended generation (DeepSeek-R1-0528, NoveltyBench Curated), though above no seed on overall utility ([01 · SEED](../../../protocol/01-blocks.md#seed--external-seeding)). That is a different model and task, with no design work, so the SEED source stays runner-injected; whether to switch to a model-written string is a deferred decision in the backlog.

**Storyboards.** The runner adds `imageArtifactId` to each storyboard shot when it stores the shot's frame, and `clipArtifactId` when a relay link produced a clip.

**Provenance.** Every completion carries its template's id, version, hash and fidelity (`CompletionRequest.prompt`), and the gateway writes them into the hash-chained ledger entry.

**Spend authority.** The spend book in `byway.sqlite` is the source of truth for spend and the authority the caps are checked against, in demo mode too (the mock's calls are recorded at $0) ([ADR-0095](../../adr/0095-paid-calls-have-a-durable-spend-book.md); this replaces "the gateway's ledger is the source of truth"). Every paid call is admitted there at its planning estimate, marked sent just before its first provider request, and settled at its true cost; the web process and the worker share it, so each sees the other's calls in flight. `ledger.jsonl` is its hash-chained audit record: settled calls are written to it through an outbox, and every line of it is read back into the book (entries from before the book included), so a process crash, two writers or a restart neither lose nor duplicate an entry, and a busy ledger delays the entry, never the call. An OS crash or power loss can still lose a line the book had marked written (ADR-0095 names this residual): the book, and so the caps, still count the call, and the start-up report and Settings' ledger check name it. A complete line the book reads and cannot record stops paid calls until the person acknowledges it in Settings; a line changed after the book read it is reported by the ledger check, and the book keeps what it read. A call a provider answered is recorded even when a label the provider reported (the served model, the upstream host) has no canonical form: the ledger records it with U+FFFD in place of a lone surrogate, or as its JSON text when it is not a string, and the exact reply stays stored under the entry's `responseSha256` ([ADR-0083](../../adr/0083-hashed-text-is-well-formed-unicode.md)); an answer that names no served model is recorded as the requested model and flagged `priceBasis: 'assumed'` ([ADR-0095](../../adr/0095-paid-calls-have-a-durable-spend-book.md)). Verifying the ledger reports a stored line that is not an entry, or has no canonical form, and a head record that cannot be read, as broken; it does not fail on it. Settings can run that check on demand. A torn last line (an OS crash, power loss or a full disk mid-append) is set aside by the next append, which continues the chain, so later calls are still ledgered and counted. A served model with no price row is settled at the requested model's rates and the entry says so (`priceBasis: 'assumed'`, shown in Settings); a dated or versioned snapshot of a priced model is settled at that model's price ([ADR-0091](../../adr/0091-provider-edge-billing-fixes.md)). A step's paid call keeps one identity across the engine's attempts of the step (its run and memo key; [ADR-0099](../../adr/0099-paid-operations-keyed-to-their-caller.md)): while one attempt holds it (the call under way, or settled while its result is being kept), another waits for that attempt's result instead of paying again; a call whose attempt timed out or whose worker died is taken over within one lease, a fal clip the provider accepted is resumed from its stored request ids, and a call settled by an attempt that ended without keeping its result is bought again, and counted.

### 3.4 Spend

The run's budget is enforced by the gateway; when it would be exceeded the step fails with `budget-exceeded`, the run pauses on a `confirm` checkpoint ("Raise the budget by $X?"), and the UI shows the cost so far.

Admission uses planning estimates, not bounds ([ADR-0091](../../adr/0091-provider-edge-billing-fixes.md)): a call is refused when its estimated cost would take spend past a cap, and without the provider's tokenizer no pre-call count is a bound. ASCII text counts at one token per three characters, any other text at its UTF-8 bytes, an image of unknown size at the 6,400-token maximum, and output at the call's whole allowance (gpt-image's per-image output figure is a planning number). A call can settle above its reservation; settlement records its true cost and later calls are refused against it. Calls under way count their estimate against both caps. A call that may have been billed without byway learning its cost (an attempt that failed after its request may have reached the provider, or a call whose caller stopped or died while waiting) counts its estimate against the workspace cap only, until the person clears it in Settings: at once when its caller's gateway was closed (the worker's and the web process's, when byway stops cleanly; [ADR-0099](../../adr/0099-paid-operations-keyed-to-their-caller.md)), and once its 60-second lease runs out when its caller died (until then it counts as under way, against its run's cap too when it has a run); a completion or image is sent again after such an attempt only if that estimate fits the workspace cap ([ADR-0095](../../adr/0095-paid-calls-have-a-durable-spend-book.md)). Provider-reported usage that is not a finite number is recorded at the call's planning figures and flagged `priceBasis: 'assumed'`; a call whose reported figures would price it above $1,000, byway's ceiling for one call, is settled at its estimate and flagged the same way, and a call estimated above that ceiling is refused. The screens and the README say so: the cost range is an estimate, the budgets are described by what byway checks before a call, and a single call can cost twice its estimate or more (for example a refused call that Anthropic routes to another model, while decision D1 keeps those fallbacks on).

## 4. Recommending and composing

**Chooser.** The seven questions of 03 "Choosing a configuration" are data (`packages/catalog/src/chooser.ts`, `ChooserQuestion[]`); the first "yes" decides. The **intake** model reads the problem and proposes an answer, confidence and one-line rationale per question (JSON); the user can flip any answer and the routing re-runs deterministically. Fit is `strong` when the deciding answer has confidence ≥ 0.7 and `partial` otherwise. Up to two alternatives are the next "yes" answers. When no question is answered yes, the recommendation is 03's fallback, C4 Reader-Ready (`CHOOSER_FALLBACK`), as a `partial` fit with `composeSuggested: true`.

**Composer.** Design-time only (ADR-0058). The composer model receives the block registry (codes, purposes, port signatures, knobs) and the nearest canonical recipe, and returns a recipe JSON on the `workspace` channel with `kind: 'composed'`. It is parsed and validated; violations go back to the model for at most two repairs; only a recipe that validates is offered. Composed recipes may use only registered blocks, knobs within range, no study manipulations and no protocol exceptions other than those their nearest canonical recipe declares; human checkpoints for VOICE and for authorship in C6/C6a are protected. The UI shows the composed recipe as a diff from the nearest canonical one, labelled "Composed — not tested".

**Admission reads what a recipe runs (ADR-0092).** What a step does is written down once, in `@byway/recipe/semantics`, from what the runner executes: who changes the work (actor, role, produced ports), whose words go into it (a human voice, build or fix that produces the artifact), what a VOICE covers (variant, knobs, medium), the block of each role, where a loop's gate can end its body, and which operators keep a step's output. Protections come only from these. A step's declarations (`writes`, the 'voice' port, block labels, `keepsVoice`) can only add refusals, and ST12 refuses one that says less than execution, or for VOICE and block labels anything else. A protected checkpoint counts one to one, and only where every run reaches it: not in an optional, a choice, a candidate or a container, and not after a check that can end its loop's round. After each VOICE, a composed recipe has no more AI writers than its nearest recipe has after the counterpart. Nothing a pick, a keep-or-revert or a scored loop puts back may predate a person's write, on a loop's or relay's later rounds too (a pick of one leaves the chosen option held, and the next round's pick takes it back). A reused prompt must answer its step's contract in the recipe's medium and render with the slots the step fills. Starting a composed recipe admits it again: one that no longer passes, or was built from a recipe byway no longer has, is refused, and one whose explanation changed does not start until the person has seen the new one.

**Admission and execution agree on the operators (ADR-0092 stage 4).** A loop's gate needs a critic or check that reports to it on every round (ST2 `feed`), and a one-shot gate a critic of its own in its body on every run (ST10 `feed`, `metric`); a loop a person holds hands them its last round (LS1). Scope typing follows the interpreter: an audit hands on its joined critique and no score, a gate its body's critique, and `each` runs each candidate without the option set. A person's list of what to remove, or a reaction of theirs given as a critique, is asked only where its answer reaches the work on some path: an AI writer that runs takes it in, a draft of the person's own is shown it, or an AI step that decides which version or option is the work takes it in (a pick's judge, a dedupe, a keep-or-revert, a critic or check whose verdict a gate reads), outside a lens or a gate body, and what it makes or decides is the work at that point of the run, not a candidate nothing takes up (a later writer that drafts from scratch, or a later pick of candidates made before it, may still put another version in its place). In replicate or each, a step makes only its candidate's work, which reaches the work only where a pick, or an AI writer that takes the options in, takes the candidates up; a dedupe decides only which options such a step may take up. That holds by any port it fills (the critique, or the brief or taste a reaction also gives), directly or in what an AI step that takes it in makes from it (a critic's critique, an AI CUT's list, a sweep's finds, a direction, and the note each leaves beside the work; a seed's direction carries nothing of theirs, since every seed prompt renders only the problem and the string). An audit hands on what its lenses made, and what came before it only where every lens may make nothing new (a lens drops a person's empty answer); so a lens that always leaves a note replaces the notes from before the audit. A seed's direction is a note in place of the notes before it on every run that answers as its prompt asks where the prompt asks for it first (C1's; a run whose model leaves the direction out keeps the notes before it), and on some runs only where its prompt asks for the block alone, so there the notes before it may stay beside the work. It is refused where another value always takes its place first, or nothing that takes it in comes after it (ST12 `critique-unapplied`, read on the paths a run can take). Asked in replicate or each, only the candidate's own steps can take it in (ST12 `critique-per-candidate`). Asked in an audit lens or a gate's body, it is also refused where an empty answer, which is dropped there, always leaves the next fix with what came before (ST9 and ST10 `human-critique`; [ADR-0098](../../adr/0098-recipe-limits-disclosure-and-held-voice.md)). Which path a run takes is decided as it runs, by the person's answers and by everything else it reads as it goes: what its AI, media and tool steps return, its random draws, and the recipe's counts. So an admitted answer may go unapplied on a run the person did not choose. For example, an AI list or sweep that finds nothing means the fix after it asks no model; a gate may end the round at its critic or check before the writer; a judge in a relay link may have no clip to see, or see one and put its critique in place; and on a storyboard of one shot, an answer that only the next link takes in goes unapplied.

**Limits, by who sets the counts (ADR-0098).** Every recipe parses within the shape bound (64 levels of JSON, 10,000 nodes, 1 MiB) and runs within the engine's limits: 500 steps at once, 2,000 step runs at most, 3 gate retries, 2 MiB of activity inputs in flight, counted from the seeds, option lists and views the counts decide (ST3 `limit`, an invariant). `Runner.start` refuses a recipe past them (`RecipeRefused`, a 400 at web start), and so does the workflow before the run begins. A composed recipe is also held to the composed limits (COMPOSED-LIMIT): replicate 16, loop rounds 12, relay links 8, lenses 4, 32 steps at once, 400 step runs, 12 levels of operators, 100 nodes, 32 KiB.

**The diff means "runs the same" (ADR-0098).** "The same steps as …" is shown only when the two recipes' semantic projections (from the field roles: names dropped, sets sorted, a step's consumed ports in order, a seq's nesting kept; the fields the composer forces left out) are equal. A seq keeps its nesting because the interpreter reads a step's siblings: a cliché sweep asks which finds to swap only when its swap step follows it in the same seq. Otherwise each difference that matters is described in plain words (who picks, a moved quality bar, never its number, how a repeat stops early, what your words cover, whether you choose a cliché sweep's swaps, an optional's question, a route's question, a final check's re-runs, a step moved into a container, behind a check that can end its round or past your words), and anything else reads "Other technical changes that affect how it runs." (a re-nesting that changes nothing reads so too). The proposal's explainers and the estimate read the same semantics: a random pick says so, only a VOICE write is "your words", worded by what it covers, a cliché sweep says you choose its swaps exactly where you are asked, a step's findings are said to be applied only by an AI writer, running in this version, that applies them and no other critique and that every run of the step reaches (not after a loop round or relay link that runs the step again first), and the AI's directions are "for you to react to" only where your next VISION is shown them on every path, each time they are made.

**Labels (CR11).** Computed by `advisor.label(recipe)` from the study registry. The registry is empty in v1, so canonical recipes read "Untested — not yet studied" and composed ones "Composed — not tested". No UI string may claim efficacy ("research-backed", "proven", "studies show", "outperforms"); a CI check scans `apps/web` for these phrases.

**Estimates.** From the recipe's structure (replicate counts, a loop's planned rounds, steps per stage) times the profile's prices, as a low–high range, plus human minutes by checkpoint kind. The rounds a person may allow once at a loop's cap are their choice, made when asked, so the estimate does not count them.

## 5. Product UX

Apple-grade means Apple's quality bar in a web app ([ADR-0040](../../adr/0040-plain-language-recipe-first-ux.md), proposed, adopted here for the product): purpose, agency (undo where safe; clear consequences before spending), restraint, craft (alignment, density, ≤100 ms interactions), familiarity (standard shortcuts), light and dark, WCAG 2.2 AA. It must itself avoid the design tells the protocol fights (no purple-gradient hero, no eyebrow labels on everything, no card soup, at most two typefaces).

**Vocabulary (plain by default; "Show technical names" reveals codes):** stages Explore / Refine / Finish; Random spark (SEED), Your direction (VISION), Outside critique (CRITIC), Custom imagery (ASSET), Motion (RELAY), Trim (CUT), Cliché sweep (TELLS), Your words (VOICE); Your turn (checkpoint); Drafts (option set); Quality bar (hidden threshold). Recipes: C1 Landing Page Studio, C2 Idea Generator, C3 Series Writer, C4 Memo Polish, C5 Ad Video Chain, C6 Second Reader, C6a Fiction Second Reader, C7 Lean Code Review.

**Screens.**
1. **Start** — one large field, "What are you working on?", with a few example problems; attachments (paste a draft or a diff), kept with the text in this tab until a run starts. When Start is refused because the text or an attachment holds a provider key ([ADR-0088](../../adr/0088-provider-boundary-held-keys-and-media-admission.md)), the refusal says which of them held it, and the tab stops keeping only that part, until it is edited.
2. **Recommendation** — the recommended recipe as a card (name, promise, the three-stage step strip with who does each step, time and cost range, evidence label, "routing untested" note), the chooser answers as editable toggles with rationales, alternatives, and "Build my own" (compose). Primary action: "Start" with the budget shown. When recommending fails, "Try again" asks once more and shows the stored recommendation with its reasons; no recipe is ever shown or started that nobody chose; examples you add are kept in this tab until the run starts (ADR-0082); an example refused for holding a provider key ([ADR-0088](../../adr/0088-provider-boundary-held-keys-and-media-admission.md)) is named in the refusal ("Example 2 contains …"), stays on screen but is not kept in the tab until it is edited, and the others stay kept.
3. **Run** — a timeline grouped by Explore / Refine / Finish; each step a quiet row with status, cost and its outputs (thumbnails for pages, excerpts for text; a count a row states, such as a diff's files and lines, is of the whole artifact). Excerpts belong to rows, cards and thumbnails only: the views you decide in (compare, references, a step opened from the timeline) show the whole text and say so while they show only its opening, show a page as a picture of its first screen that is named for assistive technology and says it is only that, and every "Open" shows the whole artifact in a viewer (each version in a compare has its own) ([ADR-0086](../../adr/0086-run-screen-excerpts-say-so-and-decision-views-show-whole-text.md)); a "Your turn" panel that takes over when a checkpoint is open: drafts contact sheet for `pick`, side-by-side compare with Flip for `compare`, a focused editor for `write`, a list editor for `directive`, a text area for `react`, a clear yes/no for `confirm`; live cost meter against the budget; Pause and Cancel always visible. Your unsent answer is kept while you look at earlier steps, and across a reload or Back in this tab; once sent, the turn shows your answer, read-only, as Sent until byway confirms it; words left on a question that closed before you sent them are shown read-only so you can copy them ([ADR-0082](../../adr/0082-web-client-state-ownership.md)); an answer refused for holding a provider key (ADR-0088) stays in its panel but is not kept in the tab until it is edited.
4. **Result** — the deliverable: a page in a sandboxed iframe (no `allow-same-origin`; its scripts off until you turn them on for this visit, and served with a strict CSP from the artifact route, which runs a page's scripts only for a same-origin frame that asks, so a page opened top-level runs nothing; "Open in a new tab" goes to the whole-artifact viewer, [ADR-0085](../../adr/0085-generated-pages-inert-unless-a-frame-asks-with-consent.md)), rendered Markdown, an options list, a storyboard, or a diff viewer; export (HTML, Markdown, JSON, patch); "How this was made" (the steps, who did what, cost).
5. **Library** — the eight recipes with their promises and labels; start any directly.
6. **History** — past runs with status and cost; open waiting runs ("Your turn") first.
7. **Settings** — providers (configured or not, never the key), model profile, workspace budget, demo mode, "Show technical names".

**Keyboard and focus.** A control that starts something (an answer's Send, Start, the paid Start button, Build my own, adding an example image) keeps keyboard focus while it is on its way and after a refusal: it is marked unavailable (`aria-disabled`, `aria-busy`), never natively disabled, and a second press does nothing. On Start and the paid Start button that is the only guard against starting twice, since run start has no server-side idempotency. Controls that make themselves unavailable ("Choose all", "Clear") keep focus the same way. A new attachment or example takes focus in its first field, so focus is not lost when the button that added it goes or becomes unavailable at the limit. Closing a step opened from the timeline returns focus to its row; with a question open, the Your turn panel takes it. A keyboard spec checks these in a real browser; it reads focus and the browser's accessibility tree, never an audit library on generated pages (apps/web README, Guardrails).

**Demo mode.** With no keys, or when forced, the gateway's mock provider returns deterministic, plausible outputs for every role and medium so the whole product is navigable; a quiet banner says "Demo mode — sample outputs, no AI calls".

## 6. Credibility guardrails in the product

- Product recipes and runs live on the `product`/`workspace` channels; product data lives in the product data directory and never feeds a study (ADR-0041 rule 3).
- Labels are computed; claims are linted (section 4).
- Product code never imports evaluation instruments (CR12); a CI check enforces the import boundary.
- Every model call goes through the gateway and its ledger (CR7-style hash chain).

## 7. Work packages

Each package is built test-first in its own git worktree under `.worktrees/<name>` on branch `product/<name>`, against `packages/contracts`. Workers must not edit `packages/contracts`, root config files or another package's files; if a contract change is truly needed they stop and report it.

**Phase 1 (parallel):**

- **WP-A catalog** (`product/catalog`): add the IR operators the 03 wirings need (at least parallel audit `{{ A ‖ B }}`; any of lanes, one-shot gate with retry, relay chain that C2–C7 and C6a require), their validator rules, the protocol-declared exceptions of 03's table (clause-scoped), and recipes `c2`, `c3`, `c4`, `c5`, `c6`, `c6a`, `c7` on the `protocol` channel with their `medium`; presentation data for all eight (`RecipePresentation`) and chooser data (`ChooserQuestion[]`); conformance tests as for C1 (each validates with exactly its exceptions, each exception needed, drift test). Existing recipe hashes must not change.
- **WP-C gateway** (`product/gateway`): `@byway/gateway` implementing `Gateway` with Anthropic, OpenAI, Google, OpenRouter (pinned provider, no fallbacks) and mock providers; verified model ids and a dated price table; profiles (`balanced`, `best`, `demo` at least, plus OpenAI/Google profiles when keys exist); `.env.agents` loading; hash-chained JSONL ledger; workspace and run caps with pre-call estimates; retries; the mock's deterministic responders for every role and medium (driven by `purpose`). No network in tests.
- **WP-S store** (`product/store`): `@byway/store` implementing `Store` and `ArtifactStore` with `node:sqlite` and content-addressed files; migrations; WAL; per-run event sequence; tests on temp directories.
- **WP-F web** (`product/web`): `apps/web` with every screen and checkpoint UI of section 5, working against in-memory demo services that implement the contracts; design system (tokens, light/dark); accessibility; unit tests for view logic.

**Phase 2 (parallel, after Phase 1 merges):**

- **WP-P prompts** (`product/prompts`): `@byway/prompts` with a template for every prompt id in the protocol-channel catalog recipes plus advisor and runner helper prompts; front matter (id, version, slots, output contract, fidelity: `verbatim` | `paraphrase` | `project`); strict renderer; static checks that no critic prompt contains a threshold and no generation or critic prompt contains the tell catalog.
- **WP-D runner** (`product/runner`): `@byway/runner` as section 3, the `Runner` client, the worker, the dev engine, esbuild workflow build; tests with `TestWorkflowEnvironment` and the mock gateway.
- **WP-E advisor** (`product/advisor`): `@byway/advisor` as section 4.

**Phase 3:** integrate `apps/web` with the real services; `pnpm dev` and `pnpm demo`; Playwright end-to-end tests in demo mode for at least C1, C4 and C6a; the claims and import-boundary checks; README.

**Phase 4:** adversarial review (correctness, UX, credibility guardrails, security), fixes, and a final verification run.
