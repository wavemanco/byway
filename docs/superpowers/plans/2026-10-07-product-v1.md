# Product v1 Implementation Plan

> **For agentic workers:** each work package is executed by one agent in its own worktree, test-first, against `packages/contracts`. Read the spec section for your package before starting.

**Goal:** Ship byway product v1 as defined in the [product v1 spec](../specs/2026-10-07-product-v1-design.md) §1.

**Architecture:** Contracts-first monorepo; eight packages and one Next.js app (spec §2), built in parallel worktrees ([ADR-0068](../../adr/0068-contracts-first-parallel-build.md)).

**Tech stack:** Node 24, pnpm 11, TypeScript, vitest, zod, node:sqlite, Temporal TS SDK 1.24 (workflows precompiled with esbuild), Playwright 1.63, Next.js 16, React 19, official provider SDKs.

## Global constraints

- Do not edit `packages/contracts`, root config files (`package.json`, `tsconfig.json`, `vitest.config.ts`, `pnpm-workspace.yaml`, `.gitignore`) or another work package's files. Adding dependencies to your own package (and the resulting `pnpm-lock.yaml` change) is fine.
- No network in tests; no real API keys anywhere; never log, store or render a key.
- `erasableSyntaxOnly` TypeScript (no enums, no parameter properties, no namespaces); ESM; `.ts` import extensions inside packages.
- Commit often on your branch with messages ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Finish with `pnpm vitest run` and `pnpm -s typecheck` green in your worktree.
- If a contract is wrong or missing, stop and report it instead of working around it.

## Phases

| Phase | Work packages (branch) | Depends on |
|---|---|---|
| 1 | WP-A catalog (`product/catalog`), WP-C gateway (`product/gateway`), WP-S store (`product/store`), WP-F web (`product/web`) | Phase 0 (contracts, spec) |
| 2 | WP-P prompts (`product/prompts`), WP-D runner (`product/runner`), WP-E advisor (`product/advisor`) | Phase 1 merged |
| 3 | Integration: web on real services, `pnpm dev`/`pnpm demo`, Playwright e2e, claims and import checks, README | Phase 2 merged |
| 4 | Adversarial review, fixes, final verification | Phase 3 |

**Merge protocol:** merge each branch into `main` in dependency order (catalog, store, gateway, web; then prompts, advisor, runner), regenerate the lockfile with `pnpm install`, run the full suite and typecheck, and push. A failing branch goes back to its agent with the failure.
